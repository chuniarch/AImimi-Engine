可取消的请求：速查

AbortController 和 AbortSignal 的全部用法、设计一个可取消函数时要问的五个问题，以及第 23 课实验台里踩过的坑。

两个对象

controller 是开关，signal 是它自带的灯。只有开关能把灯按亮；拿到灯的人只能看它，或者登记「灯亮时叫我」。

支持版本依次是 Chrome / Firefox / Safari，来自 MDN browser-compat-data（2026-10-06 查）。

设计一个可取消的函数：五个问题

  1. 平台自己认 signal 吗？认的话（比如 fetch），把调用者的 signal 直接交给它，到此为止。
  2. 有没有第二个「该停了」的理由？有（超时、兄弟任务失败），就自己建一个开关，两个理由都来按它，按的时候写清原因：调用者的取消用 controller.abort(callerSignal.reason) 转发，超时写成超时错误。
  3. 调用之前就取消了怎么办？进门先 throwIfAborted()。
  4. 失败时抛什么？开关被按过，就抛 controller.signal.reason，不去猜错误叫什么名字；没被按过，才是真出错。
  5. 什么时候收拾？等整件事结束（包括读完正文）再摘监听、停计时器。所以要把读正文放进同一个函数，比如传一个 read 进来。

骨架

async function fetchWithTimeout<T>(url: string, options: { timeout?: number; signal?: AbortSignal },
                                     read: (response: Response) => Promise<T>): Promise<T> {
  const { timeout = 6000, signal: callerSignal } = options
  callerSignal?.throwIfAborted()
  const controller = new AbortController()
  const timerId = setTimeout(() => controller.abort(new TimeoutError()), timeout) // 换成你项目的超时错误
  const forwardAbort = (): void => controller.abort(callerSignal?.reason)
  callerSignal?.addEventListener('abort', forwardAbort, { once: true })
  try {
    const response = await fetch(url, { signal: controller.signal })
    clearTimeout(timerId) // 超时只管响应头
    return await read(response)
  } catch (error) {
    if (controller.signal.aborted) throw controller.signal.reason
    throw error // 需要的话，把 TypeError 换成你项目的网络错误
  } finally {
    clearTimeout(timerId)
    callerSignal?.removeEventListener('abort', forwardAbort)
  }
}

本项目的完整版（带注释、项目的错误类）见 第 23 课第 8 节。

踩过的坑（第 23 课实验台）

  • 只给 fetch 自己的开关，忘了转发：超时有了，调用者的取消却丢了（第 3 版）。
  • 转发时 abort() 不带原因：照样能停下，但调用者收到的是浏览器新造的 AbortError，不是自己写的原因。
  • 先取消、后调用：监听永远等不到事件，请求照常发出（第 4 版）。
  • 从不收拾：每次请求都在调用者的 signal 上留下一个监听；计时器在函数结束后还会按一次开关（第 5 版）。
  • 计时器管到正文结束：大文件在慢网络上被误杀（第 5 版）。
  • 在返回 Response 时就收拾：读正文期间的取消传不进来（第 6 版错误示范）。
