校验地图：哪里校验，校验之后可以放心什么

这一页不讲每条规则怎么写，只回答两件事：每个位置检查哪一类东西；检查通过以后，下游的代码可以不再担心什么。读源码时遇到一串 require…、assert…、throw，先在这里找到它属于哪一行，就知道它在守什么，细节可以跳过。

一条主线：谁能知道，谁就检查

同一个错误，越早发现越好；但很多事早的时候还不知道。所以检查分三层，每一层只检查它此刻能知道的事（第 31 课第 8 节）：

层什么时候只看什么通过之后可以放心这时还不知道的
① 构造时new Geometry(…)、new Material(…) 这些 CPU 对象被创建、被修改的那一刻对象自己这个对象自洽；值已经复制并冻结，外面再改原数组也影响不到它它会和谁配在一起；跑在哪块显卡上
② 每帧提取时Renderer.render 开头，RenderListBuilder.build这一帧的组合：场景、相机、物体的世界矩阵这一帧交给 Pass 的值都是冻结的、有限的；相机矩阵可逆shader 要的东西 Geometry、Material 给没给；设备支不支持
③ 上 GPU 时第一次用到某个资源时（建 GPU 对象）；每次进 scope、每次 draw跨资源的配合、设备能力、GL 的回答这次 draw 的每个 active uniform 和 attribute 都有值、类型对；用到的 GPU 对象在当前 context 上完整可用—

例子：new Material({ parameters: { uColor: … } }) 时只能确认 uColor 是合法的 vec3；这个材质配的 shader 里到底有没有 uniform vec3 uColor，要等第一次 draw、program 链接好以后才知道。所以「名字对不对得上」不可能在构造时检查，只能在第 ③ 层。

每一处在守什么

源码位置相对 src/rendering/。「之后放心」一栏是下游代码依赖的前提；「留给」一栏是这一处故意不管、交给后面哪一层的事。

位置层检查什么（一句话）之后放心留给
resources/VertexAttribute①数据是支持的 TypedArray，itemSize 合法数据是自己的副本shader 用不用这个属性 → 顶点输入
resources/Geometry①有 position、至少一个顶点、各属性顶点数一致、索引不越界上传和绘制不会读越界设备支不支持 32 位索引 → GeometryManager
resources/ShaderModule①名字、语言、两段源码非空，内建映射合法文本层面完整能不能编译、链接 → ProgramManager
resources/ParameterBlock（10 月 19 日录入；第 45 课）①label 非空；名字和值的种类构造时定死，值按 Material 同一套规则复制（resources/materialParameters）；set 只能替换已有的名字、种类不变，先检查、复制再替换块里永远是完整合法的一组值；读出去的是副本shader 里有没有这些名字 → Uniforms（只问 active uniform，块里多余的项被忽略）；什么时候写块 → 生产者的约定（运行时不拦）
resources/Material①shader 存活；参数名和类型合法、数值有限、长度对；纹理存活；不占内建 uniform 名；渲染状态合法；借用的块存活，块与块、块与本地参数、块与内建名都不重名；setParameter 不许写块提供的名字参数是副本；每个名字只有一个来源，后端找值不需要优先级shader 里有没有这个 uniform、类型一不一致、缺不缺值 → Uniforms
resources/RenderTarget①label 必填；尺寸是正整数；格式和过滤在允许列表里描述冻结；改尺寸会让 revision 加 1设备能不能建（浮点、尺寸上限、FBO 完整性）→ RenderTargetManager
resources/Texture2D、CubeTexture①来源已经加载、尺寸和格式组合合法像素是快照WebGL1 的非 2 的幂、sRGB、浮点限制 → 纹理 Manager
scene/SceneNode、Transform、Mesh①树没有环、一个节点只有一个父；变换是有限的 Float32；Mesh 引用的资源存活遍历不会死循环资源中途被释放 → Mesh 的 getter 每次用时再查
scene/cameras/PerspectiveCamera①0 < fovY < π、aspect > 0、0 < near < far投影矩阵有限、不退化相机的世界矩阵可不可逆 → RenderListBuilder
frame/RenderListBuilder②view 的形状、Scene 没被释放、相机世界矩阵可逆、矩阵是 16 个有限数本帧的 ViewState、RenderItem 冻结；每个 Pass 看到同一份—
Renderer、passes/RenderPipeline②状态（运行中、关闭中、已释放）、不可重入、同一个 Pass 不进两次；Backend 没准备好就整帧跳过一帧要么完整走完，要么一个 Pass 都不跑—
backend/webgl1/WebGL1SurfaceScope③ 每次进门目的地描述合法、目标存活、清屏值在范围内；scope 里不许改尺寸或释放；读的不是正在写的目标出门一定绑回进门前的目标和 viewport—
WebGL1Backend.draw③ 每次 draw当前这一代、已就绪、在 scope 里、提交的形状对下面各 Manager 收到的是同一代的有效输入—
各个 Manager（Program、Geometry、Texture、RenderTarget）③ 第一次用到设备能力（扩展、尺寸上限）、GL 错误、编译链接结果、FBO 完整性；失败时回滚缓存表里只有完整可用的 GPU 对象，没有半成品—
WebGL1Uniforms.prepare③ 每次 draw每个 active uniform 都有值（内建、材质参数、借用的块三处找）、类型一致、sampler 数不超上限、没有 uniform 数组upload 不会写到一半失败—
顶点输入（WebGL1VertexInputSupport）③ 每次 drawshader 的每个 active attribute 在 Geometry 里都有、itemSize 是 1–4、不超属性上限draw 读到的都是绑好的缓冲—
WebGLContextLifecycle随时context 丢失、恢复旧一代的 GPU 对象不会被误用；恢复后从 CPU 对象重新建—

报错类型说明了什么

看错误名就知道是哪一类问题、该改哪里（第 6 课第 4 节）：

错误意思该改什么
Invalid…Error（Material、ParameterBlock、Geometry、RenderTarget、RenderView……）输入写错了传进来的数据
ResourceDisposedError用了已经释放的资源谁拥有、谁释放的安排
Unsupported…Error这台设备或这种组合做不到换一种格式或做法
ShaderCompilationError、ProgramLinkError、IncompleteFramebufferError、WebGLOperationErrorGL 拒绝了shader 源码、格式组合
WebGLContextLostError设备丢了不用改，等恢复
RenderExecutionError、RenderTargetUnavailableError调用的时机或顺序违规：重入、scope 里改尺寸、读写同一个目标Pass 的编排
