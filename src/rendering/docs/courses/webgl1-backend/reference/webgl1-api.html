0. 五种失败通道

WebGL 的失败几乎从不抛 JavaScript 异常。能抛异常的只有参数类型错误（例如 bindBuffer 收到的不是 WebGLBuffer，会抛 TypeError）。其余失败都走下面五条通道之一，所谓校验，就是在每条通道上主动去问。

通道典型 API怎么发现项目里的对应
① 特殊返回值 createShader → null、getAttribLocation → -1、getUniformLocation → null、getExtension → null、getActiveAttrib → null 判 === null、< 0；不要用真假值，0 是合法的 location requireNonNull、ProgramManager.ts:156
② 状态查询 COMPILE_STATUS、LINK_STATUS、checkFramebufferStatus 必须主动问；编译失败时 getError 仍然是 NO_ERROR 实测 ShaderCompilationError、ProgramLinkError、IncompleteFramebufferError
③ 错误标志 几乎所有调用：参数取值或状态不合法（INVALID_ENUM、INVALID_VALUE、INVALID_OPERATION），以及 OUT_OF_MEMORY getError()。它会同步等待 GPU，只放在冷路径；错误会一直攒着，所以开工前先清一次（preflight） checkError、assertTextureOperation → WebGLOperationError
④ context 丢失 任何时刻都可能发生；丢失后所有调用变成空操作，返回默认值（null、-1、FRAMEBUFFER_UNSUPPORTED），create* 返回已经作废的对象 实测 isContextLost() 和 webglcontextlost 事件；跨过一次查询或回调之后要再查一次 assertAvailable → WebGLContextLostError、WebGLContextLifecycle
⑤ 静默失败 纹理不完整（NPOT、缺 mipmap）采样出黑色；attribute 没 enable，读到的是常量；uniform location 为 null 时上传被悄悄忽略；上一个物体留下的状态 只能靠事前校验和最终的像素验收（readPixels） validateStorage、Manual 策略清理遗留的 location、浏览器 GPU 验收

判断标准（MDN WebGL best practices）：「The only errors a well-formed page generates are OUT_OF_MEMORY and CONTEXT_LOST.」凡是出现 INVALID_*，都说明代码有 bug。

还有一条要记住：报错的地方不一定是犯错的地方。例如先调用 pointer、后绑定 buffer（offset 为 0 时），错误要到 drawArrays 才出现；给 bufferData 传普通数组，只会得到 0 字节的 buffer，错误同样拖到 draw 时才出现。

A. context 与查询

canvas.getContext('webgl')

canvas.getContext('webgl', attributes?): WebGLRenderingContext | null

作用
创建（或取回这个 canvas 已有的）WebGL1 context。attributes（alpha、depth、stencil、antialias、premultipliedAlpha、preserveDrawingBuffer、powerPreference……）只在第一次创建时生效。

本项目
尚未出现：由 WebGL1Backend.create 负责 T15。本课程的沙盒每次运行都会调用一次。
相似
getContext('webgl2') → WebGL2RenderingContext；WebGPU 用 canvas.getContext('webgpu') 加 navigator.gpu.requestAdapter()。

isContextLost 新后端独有

gl.isContextLost(): boolean

作用
读取「context 丢失」标志。丢失以后，大部分调用变成空操作并返回默认值，不会抛异常。所以它是其它一切校验的前提。
失败
本身不会失败。
校验
项目在两种地方查它：① 每个入口（assertAvailable）；② 跨过一次 GL 查询、create* 或外部回调之后再查一次，避免把丢失期间返回的 null 当成「不支持」，或者把作废对象当成正常对象。
本项目
后端共 34 处。典型：Capabilities.ts:41 和 :53（探测前后各查一次）；State.assertContextAvailable；ProgramManager.ts:298（紧跟在 createShader 之后）。
相似
webglcontextlost 和 webglcontextrestored 事件（异步通知，见 WEBGL_lose_context）；WebGPU 用 device.lost Promise。
出处
MDN · WebGL 1.0 规范（context lost 相关章节）

getError

gl.getError(): GLenum

作用
取出并清除一个错误标志。可能的值：NO_ERROR（0）、INVALID_ENUM（0x500）、INVALID_VALUE（0x501）、INVALID_OPERATION（0x502）、OUT_OF_MEMORY（0x505）、INVALID_FRAMEBUFFER_OPERATION（0x506）、CONTEXT_LOST_WEBGL（0x9242，只在丢失后第一次调用时返回）。
失败
—（它本身就是报告通道 ③）
校验
① 它会同步等待 GPU 进程（MDN：会引起 flush 和一次往返），只放在创建、上传这类冷路径，不放在每帧的热路径；② 错误会攒着：开工前先清一次，免得把前面遗留的错误算到自己头上；③ compile/link 失败不会在这里出现，要查状态；④ 每种错误各一个标志，每次调用只取出其中一个（顺序不保证），要全部取干净得循环到 NO_ERROR（ES 2.0 参考页）实测。项目的 checkError 只取一次，靠检查点排得密来限制误报（第 2 课讨论）。
本项目
ProgramManager.checkError（第 99 行是 preflight：「发现既有 GL 错误时停止」）、GeometryManager.checkError、assertTextureOperation、VertexInputSupport.checkError。四处都是「查 lost → getError → 再查 lost」。
相似
WebGL2 相同；WebGPU 用 device.pushErrorScope() / popErrorScope()（异步）。
出处
MDN · MDN best practices

getParameter

gl.getParameter(pname: GLenum): any

作用
读 context 的全局状态或设备上限，返回类型随 pname 而变：
  • 绑定类 → 对象或 null：ARRAY_BUFFER_BINDING、ELEMENT_ARRAY_BUFFER_BINDING（属于当前 VAO）、FRAMEBUFFER_BINDING、RENDERBUFFER_BINDING、CURRENT_PROGRAM、TEXTURE_BINDING_2D / TEXTURE_BINDING_CUBE_MAP（当前纹理单元上的绑定）
  • VIEWPORT → Int32Array(4) 实测
  • 上限 → number：MAX_VERTEX_ATTRIBS、MAX_TEXTURE_IMAGE_UNITS、MAX_TEXTURE_SIZE、MAX_CUBE_MAP_TEXTURE_SIZE、MAX_RENDERBUFFER_SIZE
  • 像素存储 → number 或 boolean：UNPACK_ALIGNMENT、UNPACK_FLIP_Y_WEBGL……；ACTIVE_TEXTURE → GLenum
失败
不认识的 pname → INVALID_ENUM 并返回 null；丢失时返回 null。
校验
返回值是 any：先放进 unknown，再验证类型和范围（reqiurePositiveLimit、requireTextureLimit）；查完再查一次 lost。它也是同步调用，热路径上不要用来「核对状态」——这正是 WebGL1State 选择用 JS 缓存的原因（State.ts:88–120 的长注释）。
本项目
19 处，两种用途：① 查能力上限（Capabilities.ts:50–51、RenderTargetManager.validate）；② 「保存 → 修改 → 恢复」绑定：GeometryManager.ts:133–134、RenderTargetManager.ts:211–212、TextureUploadSupport.ts:67–74、State.captureSurfaceState、ProgramManager.ts:232（CURRENT_PROGRAM）。
相似
查某个对象或某个 location 的属性，而不是全局值：getBufferParameter、getTexParameter、getRenderbufferParameter、getFramebufferAttachmentParameter、getVertexAttrib、getShaderParameter、getProgramParameter；查某个开关：isEnabled。
出处
MDN

INVALID_VALUE：尺寸超出上限或为负、border ≠ 0；INVALID_ENUM：format 或 type 不认识；INVALID_OPERATION：internalformat ≠ format、数组类型和 type 不匹配、数据量不够（按 UNPACK_ALIGNMENT 计算行对齐）实测；还有 OUT_OF_MEMORY。
校验
WebGL1 规则：internalformat 必须等于 format；UNSIGNED_BYTE 配 Uint8Array；FLOAT 配 Float32Array，并且需要 OES_texture_float；sRGB 需要 EXT_sRGB，而且这时 format 也要写成 SRGB_EXT 或 SRGB_ALPHA_EXT。图片要先检查已经加载完成，尺寸用 naturalWidth，不要用 CSS 宽度（imageDimensions）。
本项目
CubeTextureManager.ts:126（数组）和 :128（图片）；RenderTargetManager.ts:237（null，只分配）。
相似
texSubImage2D：更新一部分，不重新分配；copyTexImage2D：从当前 framebuffer 复制；compressedTexImage2D：压缩格式；WebGL2 的 texStorage2D：一次性分配、之后尺寸不可变。
出处
MDN

texParameteri

gl.texParameteri(target, pname, param): void

作用
设置采样参数。TEXTURE_MIN_FILTER：NEAREST、LINEAR，或 4 种 *_MIPMAP_*；TEXTURE_MAG_FILTER：NEAREST、LINEAR；TEXTURE_WRAP_S / TEXTURE_WRAP_T：REPEAT（默认）、CLAMP_TO_EDGE、MIRRORED_REPEAT。
失败
INVALID_ENUM。更要命的是静默失败：MIN_FILTER 的默认值是 NEAREST_MIPMAP_LINEAR 实测，它需要完整的 mipmap 链。只上传了 level 0 却没改 MIN_FILTER，纹理就处于「不完整 (incomplete)」状态，采样结果是黑色，而且不报任何错。
校验
WebGL1 的 NPOT 规则：宽或高不是 2 的幂时，必须用 CLAMP_TO_EDGE，MIN_FILTER 只能是 NEAREST 或 LINEAR，而且不能有 mipmap，否则采样失败（MDN）。项目在上传前就拒绝不合规的组合（CubeTextureManager.ts:217–225）。
本项目
CubeTextureManager.ts:148–159（按 sampler 描述映射）；RenderTargetManager.ts:249–252（颜色附件固定用 LINEAR 加 CLAMP_TO_EDGE，所以 NPOT 尺寸的目标也能用）。
相似
texParameterf、getTexParameter；WebGL2 去掉了大部分 NPOT 限制；EXT_texture_filter_anisotropic。
出处
MDN · MDN：NPOT 规则

pixelStorei

gl.pixelStorei(pname, param): void

作用
决定上传时怎样解释 CPU 内存里的像素（这些都是全局状态）：
  • UNPACK_ALIGNMENT（默认 4，只能取 1、2、4、8）：每一行的起始地址按几个字节对齐。宽 3 像素的 RGB 图每行 9 字节，按默认的 4 字节对齐会被当成每行 12 字节，于是数据不够（INVALID_OPERATION）或者错位 实测。
  • UNPACK_FLIP_Y_WEBGL（默认 false）：上传时上下翻转（图片的原点在左上角，纹理坐标的原点在左下角）。
  • UNPACK_PREMULTIPLY_ALPHA_WEBGL（默认 false）：上传时把 alpha 乘进 RGB。
  • UNPACK_COLORSPACE_CONVERSION_WEBGL（默认 BROWSER_DEFAULT_WEBGL，可以设成 NONE）：是否让浏览器做颜色空间转换。
  • PACK_ALIGNMENT（默认 4）：readPixels 读回方向的对齐。
失败
对齐值不是 1、2、4、8 → INVALID_VALUE 实测。
校验
因为是全局状态，上一次谁设成了什么都会影响这一次上传：要么每次都显式设成确定的值（three.js 的做法），要么「保存 → 设成确定值 → finally 恢复」（本项目的做法）。
本项目
withTextureUploadState（第 79–82 行设成 1 / false / false / NONE，第 88–91 行恢复）。
相似
three.js uploadTexture（每次按纹理的属性设置）；WebGL2 增加了 UNPACK_ROW_LENGTH、UNPACK_SKIP_PIXELS 等参数。
出处
MDN

uniform1f / uniform1i / uniform2fv / uniform3fv / uniform4fv / uniformMatrix3fv / uniformMatrix4fv T15
