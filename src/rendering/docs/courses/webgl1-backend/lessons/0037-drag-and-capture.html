拖动：把一串事件变成「挪了多少」，以及指针捕获

上一课看到，一次拖动是一串事件：pointerdown、很多个 pointermove、pointerup。这一课用它们拖动一个方块。第 1 版十几行就能拖，但有个 bug：拖出舞台再松手，方块会一直粘在手上。修它要用到「指针捕获」。然后再把「拖动可能怎样结束」列全，最后对照项目的轨道控制，看它的每一行对应这里的哪一步。

1. 第 1 版：记住「在不在拖」和「上一次在哪」

每个事件都是浏览器对监听函数的一次新调用。函数里的局部变量，调用结束就没了。可拖动需要跨事件记住两件事：

  • 现在是不是在拖。鼠标只是划过时也有 pointermove，它们不该挪方块。
  • 上一个事件时指针在哪。这一次的位置减去上一次的位置，就是这一次挪了多少，记作 dx、dy。

所以把它们放在监听函数外面的变量里。这种跨事件保存的变量叫状态 (state)。实验台这次多给了一个方块 box（舞台里那个红色方块），代码改它的 style.left、style.top（CSS 规则让方块中心对准这个点）：

2. 第 1 版的 bug：拖出舞台再松手

用上面的第 1 版做这个实验：

  1. 在舞台上按住左键；
  2. 一直按着，把鼠标拖出舞台（拖到上面的代码区就行）；
  3. 在舞台外面松开；
  4. 不按任何键，把鼠标移回舞台里，晃一晃。

方块还跟着鼠标走，记录里只有 down、一串 move，没有 up。原因：

  • 事件只交给「指针下面那个元素」。你在舞台外面松开，pointerup 发给了外面的元素，舞台上登记的函数根本没被调用。
  • 所以 dragging 一直是 true。鼠标回到舞台上，即使没按键，pointermove 也会来，第 1 版照样挪方块。

这时点一下舞台，就会收到一个 pointerup，结束这次「拖动」。可用户不该需要这样做。

3. 第 2 版：指针捕获

浏览器提供了正好用于拖动的功能：指针捕获 (pointer capture)。在 pointerdown 里调用

stage.setPointerCapture(event.pointerId)

意思是：这个指针以后的事件，不管它跑到哪里，都送到 stage。直到松开（pointerup）或者被取消（pointercancel），浏览器自动解除捕获（MDN：Pointer capture）。

参数 event.pointerId 是指针编号：每个指针一个。鼠标通常一直是同一个编号；触摸屏上每根手指各有一个，所以要告诉浏览器「捕获的是哪一个」。

4. 第 3 版：拖动还可能怎样结束

正常结束是 pointerup。可拖动还可能这样结束，一个都不能漏，否则就会出现第 2 节那种「粘在手上」：

  • pointercancel：浏览器认定这个指针不会再发事件了。比如触摸时，浏览器决定把这次滑动拿去滚动页面（第 38 课实测），或者设备断开（MDN）。
  • lostpointercapture：捕获没了。pointerup、pointercancel 之后浏览器都会自动发它；别的代码调用 releasePointerCapture、舞台被移出页面时也会发。
  • 窗口失去焦点 (blur)：按着键用快捷键切到别的窗口，松手发生在别的窗口里，这一页可能收不到 pointerup。
  • 开始拖动的键不按着了：第 36 课第 6 节，组合键时左键松开不发 pointerup。第 38 课处理。

这些情况都走同一个出口 end。另外第 3 版改用「正在拖的指针编号」dragId 代替 true/false：只有编号对得上的事件才算数，这样第二根手指、第二个指针的事件不会干扰正在进行的拖动。

试试：正常拖一次，记录里依次是 pointerup「结束拖动」、lostpointercapture「已经结束，不再处理」。end 先看编号对不对得上，第二次来时 dragId 已经是 null，就什么也不做。一个结束动作只执行一次，不管有几个事件来报告它。

再试 blur：按住拖动的同时，用快捷键切到别的窗口（比如 macOS 的 ⌘ + Tab），再切回来。记录里会有「窗口失去焦点：结束拖动」。

5. 对照项目代码

项目的轨道控制（mountOrbitCameraInput.ts:233–285）就是第 3 版，加上「左键旋转、右键平移」两种模式。逐段对照：

// 状态
第 3 版：let dragId = null
项目：  let drag = null    // 不是 null 时是 { pointerId, camera, mode, x, y }

// pointerdown
第 3 版：if (dragId !== null) return
项目：  if (closed || drag !== null || !event.isPrimary) return
        // isPrimary：只认第一根手指（第 38 课）
第 3 版：dragId = event.pointerId；lastX = event.clientX；lastY = …
项目：  drag = { pointerId: event.pointerId, …, x: event.clientX, y: … }
第 3 版：stage.setPointerCapture(event.pointerId)
项目：  canvas.setPointerCapture(event.pointerId)

// pointermove
第 3 版：if (event.pointerId !== dragId) return
项目：  if (closed || event.pointerId !== drag?.pointerId) return
第 3 版：const dx = event.clientX - lastX；lastX = event.clientX
项目：  const dx = event.clientX - drag.x；drag.x = event.clientX
        // 然后 applyPan（第 33 课）或 applyOrbit（第 35 课）

// 结束
第 3 版：pointerup、pointercancel、lostpointercapture → end；window 的 blur → end
项目：  这三个事件 → onPointerEnd；hostWindow 的 blur → endDrag

（登记那几行在 :309–318。）项目比第 3 版多了三件事：

  • setPointerCapture 包在 try 里：元素已经不在页面上时它会抛错，这时干脆不开始拖动（:245–250）。
  • endDrag 先把 drag 设成 null，再释放捕获（:108–118）。释放捕获会引出一个 lostpointercapture，它再进 onPointerEnd 时，drag 已经是 null，什么都不做。这和第 3 版 end 先查编号是同一个道理。
  • pointermove 里检查「开始拖动的键还按着吗」（:260–266），下一课讲。
