2.2 只收三角面：requireTriangleFaces

function requireTriangleFaces(text: string, url: string): number {          // loadHW2OBJ.ts:44–74
  let faceCount = 0
  for (const [lineIndex, rawLine] of text.split(/\r?\n/).entries()) {       // 按原始行扫描，错误里的行号从这里来
    const line = rawLine.split('#', 1)[0]!.trim()                           // 去掉 # 之后的注释
    if (line.length === 0) continue
    const fields = line.split(/\s+/)                                        // 'f 1 2 3' → ['f', '1', '2', '3']
    if (fields[0] !== 'f') continue                                         // 只看面
    if (fields.length !== 4) throw new ResourceLoadError('model', url, {   // f 加 3 个角 = 4 段，否则拒绝
      reason: 'HW2 PRT requires exactly three corners per OBJ face', line: lineIndex + 1, cornerCount: fields.length - 1 })
    faceCount++
  }
  if (faceCount === 0) throw new ResourceLoadError('model', url, { reason: 'OBJ contains no triangle faces' })
  return faceCount                                                          // 最小例子返回 2，留给 2.4 核对
}

几点说明：

  • 为什么多个 Mesh 不行。多个 o 时位置分散在几个 Mesh 里，要不要拼、按什么顺序拼回一串，加载函数无法确认，所以干脆拒绝。旧引擎是把所有 group 拼起来，注释自己承认这要靠「group order matching face order」（createPRTSHRenderer.ts:79–103）。
  • 没有索引这一条是防御：OBJLoader 本来就不建索引（第 20 课第 8 节），万一以后换了解析器，「按面展开」这个前提要先确认还在。

检查没有它会怎样实测
① 入口fetchWithTimeout 是调用时才给 signal 挂 abort 监听（旧版 http.ts:20–22；10 月 7 日重写后进门先 throwIfAborted，见 http.ts:111）。signal 早已取消的话，abort 事件已经发生过，监听永远不会触发（第 20 课第 10 节），请求照样发出、照样返回signal 预先取消：loadHW2OBJ 抛 AbortError，fetch 一次都没调用

③ 返回前从 ② 到 ③ 之间没有 await，JavaScript 不会在中途运行别的代码，signal 的状态不会变现在触发不了，见审查视角第 1 条

function requireLines(text: string, kind: string, url: string): string[] {  // :36–46
  const trimmed = text.trim()                                               // 只去掉整个文件两端的空白
  if (trimmed.length === 0) throw new ResourceLoadError(kind, url, { reason: 'PRT file is empty' })
  return trimmed.split(/\r?\n/)                                             // 中间的空行保留，让下面的宽度检查把它揪出来
}

function parseRow(line: string, expectedCount: number, kind: string, url: string, lineNumber: number): number[] {   // :54–87
  const trimmed = line.trim()
  const fields = trimmed.length === 0 ? [] : trimmed.split(/\s+/)           // 空行是 0 个字段，不是 1 个空字段
  if (fields.length !== expectedCount)                                      // light 要 3 个，transport 要 9 个
    throw new ResourceLoadError(kind, url, { reason: 'Unexpected PRT row width', line: lineNumber, expectedCount, receivedCount: fields.length })
  return fields.map((field, column) => {
    const value = Number(field)
    if (!Number.isFinite(value))                                            // NaN、Infinity 都不要
      throw new ResourceLoadError(kind, url, { reason: 'PRT coefficient must be a finite number', line: lineNumber, column: column + 1, received: field })
    return value
  })
}

实现分两层清理：

  • 每张图一个 loadFace（:19–79）：成功、失败、取消、超时（6 秒）四个出口都调用 cleanup（:27–32），把 onload、onerror 设为 null，移除 abort 监听，清掉计时器；失败和取消还要多做一步，移除 src，尽力让浏览器放弃这次请求（:35–41）。
  • 本地 controller 统管 6 个 loadFace：任何一张失败，catch 里就 controller.abort(error)（:157–159），其余几张随即各自清理。注释特意写明这一行不能省：Promise.all 自己不会取消其余的 Promise（:96–97）。调用者的 signal 只往下转发，失败时不会被反向改成已取消（:93–94）。

还有三条规矩：

  • 成功交付之后，就不能再碰这些图片。CubeTexture 的 images 模式只借用图片、不复制（第 12 课）。要是加载函数还挂着旧 signal 的监听，用户后来一换场景，旧 signal 一取消，它就把新场景正在用的图片 src 清空。所以成功时有两道保险：每个 loadFace 成功时已经移除了自己的监听（:30、:56），整个函数结束时 finally 再移除转发（:160–162）。测试先成功、再取消旧 signal，要求 6 张图的 src 原封不动（测试 :138–147）。
  • load 事件不等于有像素。onload 里先查 complete、naturalWidth、naturalHeight，宽或高是 0 就走失败出口（:50–53）。
  • 只查和后端无关的尺寸规则。正方形、一样大，用的是和 CubeTexture、WebGL1CubeTextureManager 同一个 assertValidCubeFaceDimensions。宽高是不是 2 的幂（NPOT）只是 WebGL1 的限制，留给后端的 Manager（第 12 课 5.2 节）。

7. 属性名：新旧代码共用一个 position

5.1 的 Geometry 里，位置属性叫 position。这一节讲两件事：为什么 shader 里也必须叫 position；为了做到这一点，新旧两套代码各改了什么。

7.1 新后端：从 shader 出发按名字找，缺了就报错

新后端有两条规则：

  • Geometry 必须有 position。新的 Geometry 必须有一个叫 position 的属性，顶点数就是从它数出来的（Geometry.ts:198–202）。这个名字不是各处随手写的字符串，而是 VertexAttributeSemantic.Position（VertexAttributeSemantic.ts:12–17）。createHW2PRTGeometry 和 createHW2Scene 都用它（createHW2PRTGeometry.ts:150、createHW2Scene.ts:189）。
  • shader 要的属性，Geometry 里必须都有。画的时候，后端从 program 出发：shader 里的每个活动属性 (active attribute)，都要在 Geometry 里找到同名的属性，找不到就抛 UnsupportedRenderFeatureError（WebGL1VertexInputSupport.ts:80–90）。

所以 shader 里必须写 attribute vec3 position;。要是写成 aVertexPosition，第一次 draw 就会报 missing active attribute aVertexPosition。

8.3 取消只往下传

分两层，是因为「我的一个请求失败了」和「调用者不要这次结果了」是两件事：前者只该取消这一次构建的兄弟请求，不该把调用者的 signal 改成已取消。第 20 课 10.3 节的子 controller 写法，就是这里的简化版。

10.1 对照 three.js 的加载器

10.2 审查视角：五处值得讨论，一道找茬题

  1. 第三道取消检查现在触发不了。loadHW2OBJ 的 :117 之后到 :163 全是同步代码，JavaScript 不会在中途运行别的代码，signal 的状态不会变；catch 里的 :185 同理。createHW2Scene 返回前的那次检查（:385）也一样。想一想：它们是多余的吗？什么时候会变得有用？比如将来把大文件的解析拆成几段、中间让出主线程。
  2. fetchWithTimeout 的三个毛病：对已取消的 signal 视而不见，从不移除监听，取消时丢掉调用者的原因。它在调用时才 addEventListener（旧版 http.ts:20–22），监听里调用的是内部 controller 的 abort()，不带原因（2.7，8.4 实测 B）。10 月 7 日更新：你按第 23 课重写了 fetchWithTimeout（提交 d2e6cdf）：进门 throwIfAborted，finally 里摘掉监听，abort 时带上调用者的原因，这三个毛病都修了（http.ts:102–147）；下面说的上层补救现在成了多出来的保险。上层各补了一部分：两个加载函数在入口检查取消；createHW2Scene 给每次构建新建一个子 signal，fetchWithTimeout 挂上去的监听随这次构建一起被回收；它的 catch 再把取消原因换回来。想一想：如果改用 AbortSignal.any 把外部 signal 和 AbortSignal.timeout 合成一个交给 fetch，三个问题都会消失吗？
  3. Promise.all 一个失败，另一个请求还在跑。单看 loadPRTSHTxt，light.txt 404 时 transport 的请求没人取消（8.4 实测 C2）。createHW2Scene 用子 AbortController 在上一层解决了（实测 C）；loadHW2CubeImages 对自己的六张图也是同样的做法。想一想：这个职责放在工厂里，比放在 loadPRTSHTxt 里更合适吗？
  4. 新版 PRTData 的 vertexCount 和「三参数兼容」没人用。Task 22 以后，旧的 createPRTSHRenderer 没有调用者了，新版唯一的调用者 createHW2Scene 总是传 signal，也不读 vertexCount（3.3）。可注释和测试还在为「旧调用者」保留这两样（loadPRTSHTxt.ts:14–15、:96；测试「保留三参数调用兼容性」）。想一想：现在可以删了吗？留着有什么代价？
  5. loadHW2OBJ 的 lint:prod 错误已经修好。这一课第一版写的时候，代码里直接用 mesh instanceof ThreeMesh。ThreeMesh 是泛型类，这样收窄出来的是 Mesh<any, any, any>，mesh.geometry、node.material 都成了 any，ESLint 报了 6 个 @typescript-eslint/no-unsafe-call，CI 跑的 npm run check 会因此失败。现在的代码换成了类型谓词 isThreeMesh（loadHW2OBJ.ts:25–27，参数类型是 Object3D | undefined），两处 instanceof 都改用它。2026-10-05 实测：这个文件 lint:prod 0 个错误，11 个测试通过。想一想：为什么类型谓词收窄出来的是带默认类型参数的 ThreeMesh，instanceof 却是 any？
