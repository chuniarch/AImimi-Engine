一次 draw 怎样把 CPU 资源、Pass 和 GPU 资源接起来

第 40–46 课在小引擎里一步步推出了每个零件。这一课把它们接回真实的 src/rendering：顺着一次 draw，从 Pass 交出要画的东西开始，到 gl.drawArrays 为止，看清三样东西在哪几行接上、为什么要这样接。最后用真实代码画两帧，数每一步发了哪些 GL 调用。

和你的目标的关系 —— HW1、HW2 的每一帧都走这条路。以后加阴影 Pass、GBuffer Pass，或者 FLIP 结果的可视化 Pass，都只是在这条路上多一个 Pass；判断一段新代码该放在 Pass、Material 还是 Backend 里，靠的就是这一课的三处接口。WebGPU 后端（路线 B）要实现的也是同一个 draw 合同。
和第 19 课的关系：这一课重写第 19 课。旧课停在 9 月 30 日的代码，正文把调用链拆成十几段代码，校验和主线混在一起。旧课保留（别的课里有「第 19 课 x.y 节」的引用指向它），以后读这一课就行。
默认你已经会的：① 第 30 课：Renderer 每帧抄快照、Pipeline 依次跑 Pass；② 第 40–46 课的小引擎：按对象查表（41）、画什么写成数据（42）、每帧先抄一份（43）、Pass 和进门出门（44）、值从三处找（45）、一代与丢失（46）。
在一帧里的位置和寿命：每帧 Renderer.render 抄一次快照 → Pipeline 依次跑每个 Pass → 每个 Pass 进一次或几次门 → 门里每个物体调一次 draw。draw 只活一次调用；它用到的 GPU 对象活一「代」（直到 context 丢失或 Backend 释放）；CPU 资源活在场景里，由 Scene 登记。

1. 一次 draw 要三样东西

拿第 40 课的场景说：地面上悬着一个三角形，一盏方向光，两遍画完（先画进阴影图，再画到屏幕）。要画出地面，GPU 需要 program、装着顶点的 buffer、画到哪个 framebuffer，以及一组 uniform 的值。这些东西来自三个地方：

哪一样具体是什么谁建、在哪活多久；知不知道 gl
CPU 资源Geometry（地面、三角形的顶点）、ShaderModule、Material、ParameterBlock（阴影值）、RenderTarget（阴影图的尺寸和格式）写场景的人建，Scene 登记跟着场景；不知道 gl
PassShadowMapPassV1（画进阴影图）、ForwardPass（画到屏幕）装进 RenderPipeline每帧跑一次；不知道 gl
GPU 资源program、buffer、VAO、纹理、framebufferBackend 的各个 Manager，第一次用到时建跟着 context 的一代；只有它们知道 gl

8. 延伸阅读

    

      首选（约 15 分钟）：WebGL Fundamentals 的 WebGL - Drawing Multiple Things。它把画很多个物体分成两段：初始化时建好 shader、program、buffer、纹理；每次画每个物体时 useProgram、设 attribute、设 uniform、绑纹理、drawArrays。对照这一课：第 ⑤⑥ 步第一次走冷路径，就是它的「初始化」，只是推迟到第一次用到时才做；第 ⑧⑨⑩ 步就是它的「每次画」。
