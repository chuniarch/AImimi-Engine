2. 齐次坐标与 4 × 4 矩阵

2.1 先约定写法

本课和 GLSL、gl-matrix、three.js 用的是同一种写法：向量写成一列，矩阵写在左边，p′ = A · p。三维的点补成四个数 (x, y, z, 1)，方向补成 (x, y, z, 0)，最后这个数叫 w。为什么要补一个数：平移不是 3 × 3 矩阵能做的乘法，补上 w 以后，平移也能写成矩阵乘法。用 HW2 的相机位置做例子： 

// 平移矩阵 Tr(0, 20, 50)：把东西挪到 (0, 20, 50)
// ┌ 1  0  0   0 ┐   ┌ 0 ┐   ┌  0 ┐
// │ 0  1  0  20 │ · │ 0 │ = │ 20 │   点 (0, 0, 0)，w = 1：被挪到 (0, 20, 50)
// │ 0  0  1  50 │   │ 0 │   │ 50 │
// └ 0  0  0   1 ┘   └ 1 ┘   └  1 ┘
//
// 同一个矩阵乘方向 (1, 0, 0)，w = 0：最后一列乘的是 0，结果还是 (1, 0, 0, 0)。
// 方向只有朝向、没有位置，所以平移不影响它。这正是想要的。

2.2 矩阵的每一列是什么

记矩阵 A 第 r 行、第 c 列的数为 arc（行号、列号都从 0 数）。拿 A 去乘四个最简单的列向量，看结果是什么： 

// A · (1, 0, 0, 0) = (a00, a10, a20, a30)   = 第 0 列：原来的 X 轴方向，变换后指向哪
// A · (0, 1, 0, 0) = (a01, a11, a21, a31)   = 第 1 列：原来的 Y 轴方向，变换后指向哪
// A · (0, 0, 1, 0) = (a02, a12, a22, a32)   = 第 2 列：原来的 Z 轴方向，变换后指向哪
// A · (0, 0, 0, 1) = (a03, a13, a23, a33)   = 第 3 列：原来的原点，变换后在哪
//
// 任何一个点 (x, y, z, 1) = x·(1,0,0,0) + y·(0,1,0,0) + z·(0,0,1,0) + (0,0,0,1)，所以
// A · (x, y, z, 1) = x·第 0 列 + y·第 1 列 + z·第 2 列 + 第 3 列

最后一行就是理解相机矩阵的钥匙：一个变换矩阵的四列，就是「新坐标系的三根轴」和「新坐标系的原点」。

3. 相机的 world 矩阵 C

相机也是场景里的一个节点，它有自己的坐标系：原点在镜头上，三根轴是右方 r（相机自己的 +X）、上方 u（+Y）、后方 b（+Z）。OpenGL、three.js、gl-matrix 都约定相机朝自己的 −Z 看（PerspectiveCamera.ts:104），所以前方 f = −b。

一个点在相机坐标系里的坐标是 (x, y, z)，意思是：从镜头出发，往右走 x、往上走 y、往后走 z。它在世界里的位置因此是 eye + x·r + y·u + z·b。对照 2.2 节最后一行，这正是一个矩阵乘法，而这个矩阵的四列就是 r、u、b、eye： 

//     ┌ r.x  u.x  b.x  eye.x ┐
// C = │ r.y  u.y  b.y  eye.y │      C · (x, y, z, 1) = x·r + y·u + z·b + eye
//     │ r.z  u.z  b.z  eye.z │
//     └  0    0    0     1   ┘
//
// HW2（第 5 节推出三根轴；这里先用结果）：
//     ┌ 1   0         0        0 ┐   第 0 列 r   = (1, 0, 0)               右方：世界的 +X
// C = │ 0   0.98058   0.19612  20 │   第 1 列 u   = (0, 0.98058, −0.19612)  上方：跟着低头往前倾
//     │ 0  −0.19612   0.98058  50 │   第 2 列 b   = (0, 0.19612, 0.98058)   后方；前方 f = −b
//     └ 0   0         0         1 ┘   第 3 列 eye = (0, 20, 50)
//
// 验算：相机正前方 50.99 远的点，相机坐标是 (0, 0, −50.99)
// C · (0, 0, −50.99, 1) = −50.99·b + eye
//                       = (0, −10.000, −50.000) + (0, 20, 50) = (0, 10, 0) = target

这就是第 25 课旧版里那句「world 矩阵的四列依次是相机的右方、上方、后方和位置」的来历：不是约定俗成，而是 2.2 节「列 = 新坐标系的轴和原点」直接推出来的。下面的图把这几根轴画在 HW2 的场景里。

4. view 矩阵 V：两种推导，结果一样

4.1 view space 是什么

投影要求点先换到这样一个坐标系里：相机在原点，x 朝右，y 朝上，朝 −z 看。这叫 view space（相机空间、眼空间）。拿它和第 3 节比一比：这个定义和相机自己的局部坐标系完全一样。所以 V 要做的事就是：已知一个点的世界坐标，求它的相机局部坐标。这正好是 C 的反方向。

4.2 推导一：反过来解

// C 把相机坐标变成世界坐标：  p_world = C · p_view
// 两边左乘 C 的逆：            C⁻¹ · p_world = p_view
// 所以                         V = C⁻¹

4.3 推导二：先平移，再旋转（GAMES101 的做法）

不求逆也能写出来。第一步，把相机挪回原点：所有点减去 eye。第二步，问「这个点在 r、u、b 三个方向上各走了多远」。因为 r、u、b 两两垂直、长度都是 1，在某个方向上走了多远，就是和这个方向的点乘： 

// p_view = ( r·(p − eye),  u·(p − eye),  b·(p − eye) )
//
// 写成矩阵：前三行就是 r、u、b 横着放，第 3 列是 −r·eye、−u·eye、−b·eye
//     ┌ r.x  r.y  r.z  −r·eye ┐
// V = │ u.x  u.y  u.z  −u·eye │
//     │ b.x  b.y  b.z  −b·eye │
//     └  0    0    0     1    ┘
//
// HW2：
//   −u·eye = −(0.98058·20 + (−0.19612)·50) = −(19.6116 − 9.8058) = −9.8058
//   −b·eye = −(0.19612·20 + 0.98058·50)    = −(3.9224 + 49.0290) = −52.9514
//     ┌ 1   0         0          0       ┐
// V = │ 0   0.98058  −0.19612   −9.8058  │
//     │ 0   0.19612   0.98058  −52.9514  │
//     └ 0   0         0          1       ┘
//
// 跟踪的点 p = (0, 20, 0)，p − eye = (0, 0, −50)：
//   x = r·(0, 0, −50) = 0
//   y = u·(0, 0, −50) = (−0.19612)·(−50) =   9.806    在镜头上方 9.806
//   z = b·(0, 0, −50) =   0.98058·(−50) = −49.029    在镜头前方 49.029（−z 是前方）

两种推导为什么相等：C 可以拆成「先旋转、再平移」，C = Tr(eye) · Rot，其中 Rot 的三列是 r、u、b。三列两两垂直、长度为 1 的矩阵，逆等于转置（行列互换），所以 C⁻¹ = RotT · Tr(−eye)。RotT 的三行就是 r、u、b，正是推导二的矩阵。

4.4 什么时候不只是一个逆

V = C⁻¹ 成立，靠的是「相机局部坐标系的约定」和「view space 的约定」一致。不一致时，要在中间再乘一个固定的矩阵：

  • 局部坐标系朝向不同。如果某套约定让相机朝自己的 +Z 看，就得先把它的局部坐标转成「朝 −Z 看」，比如绕 Y 轴转 180°：V = K · C⁻¹，K = Ry(180°)。three.js 的做法是让相机和其他物体朝向不同：lookAt 对相机和灯光让 −Z 对准目标，对其他物体让 +Z 对准目标（Object3D.js:688–694）。这样相机的局部坐标系就是 view space，matrixWorldInverse 一个逆就够了（Camera.js:92–97）。
  • C 里带缩放。相机或它的父节点放大了 2 倍，C 的三列就不再是长度 1，C⁻¹ 也就不等于转置。用通用的求逆仍然得到「世界 → 相机局部」，只是看到的世界会缩小一半。项目和 three.js 都用通用求逆（RenderListBuilder.ts:84 的 mat4.invert），没有利用「转置更便宜」；HW2 的相机缩放是 1，父节点 Scene 是单位矩阵。

本项目里 V 是这样来的：

// RenderListBuilder.ts:54–95（节选，注释是课程加的）
const cameraWorld = new Float32Array(16)
const viewMatrix = new Float32Array(16)
const projection = new Float32Array(16)

// ① 相机的 world matrix：先按需更新相机和祖先（第 8 课），再复制出来
camera.copyWorldMatrixTo(cameraWorld)
const world = copyMat4Snapshot(cameraWorld, 'camera.worldMatrix') // 检查 16 个数都有限

// ② view = world 的逆。world 把「相机自己的坐标」搬到世界里；
//    反过来，view 把世界里的点搬到「以相机为原点、朝 −Z 看」的坐标里
if (mat4.invert(viewMatrix, world) === null)
  throw new InvalidRenderViewError('camera.worldMatrix', 'must be invertible')

// ③ projection：PerspectiveCamera 已经算好，复制一份（第 9 课）
camera.copyProjectionMatrixTo(projection)

// ④ 相机在世界里的位置：world 第 3 列的前三个数
const position: Vec3Tuple = Object.freeze([world[12], world[13], world[14]])

const viewState: ViewState = Object.freeze({
  viewMatrix: copyMat4Snapshot(viewMatrix, 'camera.viewMatrix'),
  projectionMatrix: copyMat4Snapshot(projection, 'camera.projectionMatrix'),
  cameraWorldPosition: position
})

5. 三根轴从哪来：lookAt 与欧拉角

第 3 节先用了 r、u、b 的值。它们从哪来？最常见的给法是「相机在 eye，看向 target」。

5.1 lookAt：两次叉积

// 输入：eye = (0, 20, 50)，target = (0, 10, 0)，世界的上方 up = (0, 1, 0)
// ① 前方 f = normalize(target − eye) = normalize(0, −10, −50)
//          = (0, −10, −50) / 50.990 = (0, −0.19612, −0.98058)
// ② 右方 r = normalize(f × up)
//          f × up = (f.y·0 − f.z·1,  f.z·0 − f.x·0,  f.x·1 − f.y·0) = (0.98058, 0, 0)
//          归一化 → (1, 0, 0)
// ③ 上方 u = r × f
//          = (0·(−0.98058) − 0·(−0.19612),  0·0 − 1·(−0.98058),  1·(−0.19612) − 0·0)
//          = (0, 0.98058, −0.19612)
// ④ 后方 b = −f = (0, 0.19612, 0.98058)
//
// 为什么用 f × up 求右方：叉积垂直于两个输入，所以 r 一定和 up 垂直，
// 也就是水平的——相机不会歪头。
// 为什么 u 不直接用 up：up 和 f 不垂直（相机低着头），r × f 才是和两者都垂直的那个「上」。

three.js 的 Matrix4.lookAt 就是这几步，只是变量名不同（_z 是 b，_x 是 r，_y 是 u），算完直接写进矩阵的前三列：

// three.js r177 Matrix4.js:463–508（节选；注释是课程加的）
lookAt( eye, target, up ) {
  const te = this.elements;
  _z.subVectors( eye, target );   // 从目标指回相机：这就是后方 b（还没归一化）
  if ( _z.lengthSq() === 0 ) {
    _z.z = 1;                     // 相机和目标重合：随便给一个方向
  }
  _z.normalize();
  _x.crossVectors( up, _z );      // up × b = 右方 r
  if ( _x.lengthSq() === 0 ) {
    // 正对头顶或脚底：up 和 b 平行，叉积是 0。把 b 挪一点再算
    if ( Math.abs( up.z ) === 1 ) { _z.x += 0.0001; } else { _z.z += 0.0001; }
    _z.normalize();
    _x.crossVectors( up, _z );
  }
  _x.normalize();
  _y.crossVectors( _z, _x );      // b × r = 上方 u
  te[ 0 ] = _x.x; te[ 4 ] = _y.x; te[ 8 ] = _z.x;   // 写进第 0、1、2 列（列主序，第 7 节）
  te[ 1 ] = _x.y; te[ 5 ] = _y.y; te[ 9 ] = _z.y;
  te[ 2 ] = _x.z; te[ 6 ] = _y.z; te[ 10 ] = _z.z;
  return this;
}

// 谁调用它：Object3D.js:686–698（节选）
_position.setFromMatrixPosition( this.matrixWorld );   // eye = 自己现在的位置
if ( this.isCamera || this.isLight ) {
  _m1.lookAt( _position, _target, this.up );          // 相机和灯：−Z 朝目标
} else {
  _m1.lookAt( _target, _position, this.up );          // 其他物体：+Z 朝目标
}
this.quaternion.setFromRotationMatrix( _m1 );          // 只留下旋转，存成四元数

5.2 本项目：Transform 不存三根轴，存三个角

你问的「up 不是由 front 和 right 叉出来的吗」——是的，5.1 节就是这么算的。可本项目的 Transform 没有 lookAt，它只存三个欧拉角，用的时候由角度算出旋转矩阵（第 8 课）： 

// Transform 的 rotation = [α, β, γ]（弧度），旋转矩阵 Rot = Rz(γ) · Ry(β) · Rx(α)
//   Rx(α)：绕 X 轴转 α         Ry(β)：绕 Y 轴转 β
//   ┌ 1   0      0    ┐       ┌  cos β  0  sin β ┐
//   │ 0  cos α −sin α │       │   0     1   0    │
//   └ 0  sin α  cos α ┘       └ −sin β  0  cos β ┘
//
// 三根轴就是 Rot 的三列（2.2 节）。不歪头意味着 γ = 0，Rot = Ry(β) · Rx(α)。
// 后方 b = Rot 的第 2 列 = Ry(β) · Rx(α) · (0, 0, 1)
//        = Ry(β) · (0, −sin α, cos α)
//        = (cos α · sin β,  −sin α,  cos α · cos β)
//
// 要求 b 等于「从目标指向相机」的方向。设 offset = eye − target = (dx, dy, dz)，
// horizontal = √(dx² + dz²) 是水平距离，distance = √(horizontal² + dy²)：
//   −sin α = dy / distance          → α = −atan2(dy, horizontal) = −el   （el 叫仰角）
//   sin β : cos β = dx : dz         → β = atan2(dx, dz)          =  az   （az 叫方位角）
//
// 所以 rotation = [−el, az, 0]。HW2：offset = (0, 10, 50)，horizontal = 50
//   el = atan2(10, 50) = 0.19740 rad = 11.31°，az = atan2(0, 50) = 0
//   rotation = [−0.19740, 0, 0]              ← 就是 createHW2Scene.ts:382 写的 −atan2(10, 50)
//
// 验算：Rx(−11.31°) 的三列
//   第 0 列 (1, 0, 0)                     = r
//   第 1 列 (0, cos 11.31°, −sin 11.31°)  = (0, 0.98058, −0.19612) = u
//   第 2 列 (0, sin 11.31°,  cos 11.31°)  = (0, 0.19612,  0.98058) = b
// 和 5.1 节两次叉积的结果一模一样。

所以 [−11.31°, 0, 0] 不是另一个朝向，而是同一组三根轴的另一种记法：three.js 记的是四元数（由三根轴换算），本项目记的是三个角（由方向用 atan2 换算）。atan2(对边, 邻边) 交回一个角，它的正切等于「对边 ÷ 邻边」，而且看两个数的正负分象限：atan2(10, 50) = 11.31°，atan2(10, −50) = 168.69°。

角度怎样变回 16 个数，在 Transform 的这个函数里：

// Transform.ts:253–274（注释是课程加的）
private updateLocalMatrixIfNeeded(): void {
  if (!this.localMatrixDirty) return // TRS 没改过：直接用上次算好的 16 个数

  const rotationQuaternion = quat.create()

  // ① 三个欧拉角 → 四元数。gl-matrix 要「度」，所以乘 180/π。
  //    组合顺序是 Rot = Rz · Ry · Rx（第 8 课 2.4 节）
  quat.fromEuler(
    rotationQuaternion,
    this.rotationValue[0] * RADIANS_TO_DEGREES,
    this.rotationValue[1] * RADIANS_TO_DEGREES,
    this.rotationValue[2] * RADIANS_TO_DEGREES
  )

  // ② 四元数 + 位置 + 缩放 → C_local = Tr(position) · Rot · Scale，
  //    按列主序写进 localMatrixValue 的 16 个数（第 7 节）
  mat4.fromRotationTranslationScale(
    this.localMatrixValue,
    rotationQuaternion,
    this.positionValue,
    this.scaleValue
  )

  this.localMatrixDirty = false
}

最后一步 fromRotationTranslationScale 写进的，正是第 3 节 C 的四列：

// gl-matrix 3.4.3 mat4.js:1170–1208 的写入部分（节选；注释是课程加的）
// 前面几行由四元数 (x, y, z, w) 算出 xx、xy、wz 等中间量
out[0] = (1 - (yy + zz)) * sx;  // ┐
out[1] = (xy + wz) * sx;        // │ 第 0 列：旋转后的 X 轴 × 缩放 sx = 相机的右方 r
out[2] = (xz - wy) * sx;        // ┘
out[3] = 0;
out[4] = (xy - wz) * sy;        // ┐
out[5] = (1 - (xx + zz)) * sy;  // │ 第 1 列：旋转后的 Y 轴 × sy = 上方 u
out[6] = (yz + wx) * sy;        // ┘
out[7] = 0;
out[8] = (xz + wy) * sz;        // ┐

out[10] = (1 - (xx + yy)) * sz; // ┘

out[12] = v[0];                 // ┐

out[14] = v[2];                 // ┘

顺序不能换。同样三个数 [−30°, 60°, 0]，按 Rz·Ry·Rx 是「先低头、再绕世界竖直轴转身」；按 three.js 欧拉角默认的 'XYZ'（Rot = Rx·Ry·Rz）就成了「先转身、再绕世界 X 轴低头」，转身以后世界 X 轴已经不是相机的右方，结果歪了头。下面三张卡片把同一个朝向交给两边去算。

6. 投影矩阵 P：从视锥推出来

6.1 要达到什么

相机能看到的范围是一个截掉尖的金字塔，叫视锥 (frustum)：在 view space 里，它夹在 z = −near 和 z = −far 之间，上下张角是 fovY，左右张角由 aspect 决定。投影要把视锥里的点压进一个立方体，叫 NDC（标准化设备坐标）：x、y、z 都在 [−1, 1] 之间。约定是 x = −1 在画面左边、+1 在右边，y = −1 在下边、+1 在上边；近平面上的点 z = −1，远平面上的点 z = +1（OpenGL 的约定，gl-matrix 的函数名 perspectiveNO 里的 NO 就是「负一到一」）。

6.2 一步一步推

// 第 1 步：x、y（相似三角形，图 3）
//   深度 d = −z，那里的半高 = d · tan(fovY / 2)，半宽 = aspect · 半高
//   y_ndc = y / (d · tan(fovY/2)) = F · y / (−z)             F = 1 / tan(fovY / 2)
//   x_ndc = x / (aspect · d · tan(fovY/2)) = (F / aspect) · x / (−z)
//   HW2：F = 1 / tan(22.5°) = 2.41421，F / aspect = 1.60948
//   跟踪的点：y = 9.806，−z = 49.029 → y_ndc = 2.41421 · 9.806 / 49.029 = 0.4828
//
// 第 2 步：「除以 −z」不是矩阵乘法能做的，交给 GPU
//   让矩阵算出 w_clip = −z（第 3 行写成 0, 0, −1, 0），x_clip = (F/aspect)·x，y_clip = F·y。
//   GPU 拿到 (x_clip, y_clip, z_clip, w_clip) 以后，自己把前三个数除以 w_clip。这叫透视除法。
//
// 第 3 步：z。也要除以 w，所以设 z_clip = A·z + B，z_ndc = (A·z + B) / (−z)，要求
//   z = −near 时 z_ndc = −1：  (−A·near + B) / near = −1  →  −A·near + B = −near
//   z = −far  时 z_ndc = +1：  (−A·far  + B) / far  =  1  →  −A·far  + B =  far
//   两式相减：−A·(far − near) = far + near   →  A = (far + near) / (near − far)
//   代回第一式：B = A·near − near            →  B = 2·far·near / (near − far)
//   HW2：A = 1000.1 / (−999.9) = −1.00020，B = 200 / (−999.9) = −0.20002
//
// 合起来：
//     ┌ F/aspect   0    0    0 ┐     HW2：┌ 1.60948  0        0         0       ┐
// P = │   0        F    0    0 │          │ 0        2.41421  0         0       │
//     │   0        0    A    B │          │ 0        0       −1.00020  −0.20002 │
//     └   0        0   −1    0 ┘          └ 0        0       −1         0       ┘
//
// 跟踪的点 p_view = (0, 9.806, −49.029, 1)：
//   p_clip = (0,  2.41421·9.806,  −1.00020·(−49.029) − 0.20002,  49.029)
//          = (0,  23.673,  48.839,  49.029)
//   p_ndc  = (0,  23.673 / 49.029,  48.839 / 49.029) = (0, 0.4828, 0.9961)

z_ndc = 0.9961：离相机 49 个单位，在 [−1, 1] 里已经很靠近远端 1 了。z 除以的是 −z，所以 NDC 的深度不是均匀的：大部分精度留给离 near 很近的地方。near 设得越小，远处越不准，这是 near 不该随手设成 0.0001 的原因。

6.3 最后一步：NDC → 像素

// gl.viewport(0, 0, 900, 600) 定下换算（State.bindSurface 发出，第 14 课）：
//   x_px = (x_ndc + 1) / 2 · 900 = (0 + 1) / 2 · 900       = 450
//   y_px = (y_ndc + 1) / 2 · 600 = (0.4828 + 1) / 2 · 600  = 444.9
//          WebGL 的窗口坐标，y 从画布底边往上数
//   换成从顶边往下数（CSS、截图的习惯）：600 − 444.9 = 155.1
// 答案：这个点画在 (450, 155.1)。

代码里，P 由 gl-matrix 的 perspective 算出（PerspectiveCamera.ts:113 调用），一项一项正好是上面的式子：

// gl-matrix 3.4.3 mat4.js:1374–1403（注释是课程加的；下标 i = 4·列 + 行，见第 7 节）
export function perspectiveNO(out, fovy, aspect, near, far) {
  var f = 1.0 / Math.tan(fovy / 2), // F = 1 / tan(fovY / 2)；HW2：2.41421
      nf;
  out[0] = f / aspect;              // 第 0 行第 0 列：F / aspect；aspect 1.5 时 1.60948
  out[1] = 0;
  out[2] = 0;
  out[3] = 0;
  out[4] = 0;
  out[5] = f;                       // 第 1 行第 1 列：F
  out[6] = 0;
  out[7] = 0;
  out[8] = 0;
  out[9] = 0;
  out[11] = -1;                     // 第 3 行第 2 列：−1，于是 w_clip = −z_view
  out[12] = 0;
  out[13] = 0;
  out[15] = 0;

  if (far != null && far !== Infinity) {
    nf = 1 / (near - far);
    // 第 2 行第 2 列：A = (far + near) / (near − far)；HW2：−1.00020
    out[10] = (far + near) * nf;
    // 第 2 行第 3 列：B = 2·far·near / (near − far)；HW2：−0.20002
    out[14] = 2 * far * near * nf;
  } else {
    out[10] = -1;                   // far 取无穷大时的极限；PerspectiveCamera 不接受 Infinity
    out[14] = -2 * near;
  }

  return out;
}

three.js 走的是一条更一般的路：先算出近平面上的上下左右边界，再按「任意视锥」的公式填矩阵。视锥左右、上下对称时，结果和上面一模一样：

// three.js r177 PerspectiveCamera.js:353–381（节选；注释是课程加的）
updateProjectionMatrix() {
  const near = this.near;
  // fov 用「度」；top 是近平面上的半高
  let top = near * Math.tan( DEG2RAD * 0.5 * this.fov ) / this.zoom;
  let height = 2 * top;
  let width = this.aspect * height;
  let left = - 0.5 * width;
  // ……setViewOffset、filmOffset 会再挪 left、top；默认不挪……
  this.projectionMatrix.makePerspective(
    left, left + width, top, top - height, near, this.far, this.coordinateSystem );
}

// Matrix4.js:1108–1146（节选）
makePerspective( left, right, top, bottom, near, far ) {
  const x = 2 * near / ( right - left );   // = 2·near / (aspect·2·top) = F / aspect
  const y = 2 * near / ( top - bottom );   // = 2·near / (2·top) = F
  const a = ( right + left ) / ( right - left ); // 视锥左右对称时是 0
  const b = ( top + bottom ) / ( top - bottom ); // 上下对称时是 0
  const c = - ( far + near ) / ( far - near );   // = A
  const d = ( - 2 * far * near ) / ( far - near ); // = B
  te[ 0 ] = x; te[ 4 ] = 0; te[ 8 ] = a;  te[ 12 ] = 0;
  te[ 1 ] = 0; te[ 5 ] = y; te[ 9 ] = b;  te[ 13 ] = 0;
  te[ 2 ] = 0; te[ 6 ] = 0; te[ 10 ] = c; te[ 14 ] = d;
  te[ 3 ] = 0; te[ 7 ] = 0; te[ 11 ] = -1; te[ 15 ] = 0;
}

7. 16 个数怎么存：列主序

数学上的矩阵是 4 行 4 列。内存里只有一排 16 个数（Float32Array）。gl-matrix、three.js 的 elements、WebGL 的 uniformMatrix4fv、GLSL 的 mat4，用的都是列主序 (column-major)：先放第 0 列的 4 个数，再放第 1 列，依此类推。第 r 行第 c 列的数，放在下标 4·c + r：

第 0 列第 1 列第 2 列第 3 列
第 0 行[0]　1[4]　0[8]　0[12]　0
第 1 行[1]　0[5]　0.98058[9]　0.19612[13]　20
第 2 行[2]　0[6]　−0.19612[10]　0.98058[14]　50
第 3 行[3]　0[7]　0[11]　0[15]　1

表里方括号是下标，后面是 HW2 的 C。所以内存里的 16 个数是：

// camera.copyWorldMatrixTo(world) 之后，world 里依次是：
//   [0..3]   1, 0, 0, 0                 ← 第 0 列：r
//   [4..7]   0, 0.98058, −0.19612, 0    ← 第 1 列：u
//   [8..11]  0, 0.19612, 0.98058, 0     ← 第 2 列：b
//   [12..15] 0, 20, 50, 1               ← 第 3 列：eye
// 所以 RenderListBuilder 取相机位置写的是 [world[12], world[13], world[14]]
// （RenderListBuilder.ts:89）

你问「world 是不是数学矩阵的转置」：不是，它就是那个矩阵，只是一列一列地存。容易误会的原因是：把这 16 个数每 4 个一行打印出来，屏幕上的每一行其实是数学上的一列，看上去像转置。真正会出现「转置」的地方，是两个库给矩阵赋值的函数参数顺序不同： 

// three.js r177 Matrix4.js:121–128（注释是课程加的）
// 参数按「数学上一行一行读」的顺序给：n12 是第 1 行第 2 个
set( n11, n12, n13, n14, n21, n22, n23, n24, n31, n32, n33, n34, n41, n42, n43, n44 ) {
  const te = this.elements;
  // 存的时候按列放：数学上的第 1 行分散到下标 0、4、8、12
  te[ 0 ] = n11; te[ 4 ] = n12; te[ 8 ] = n13; te[ 12 ] = n14;
  te[ 1 ] = n21; te[ 5 ] = n22; te[ 9 ] = n23; te[ 13 ] = n24;
  te[ 2 ] = n31; te[ 6 ] = n32; te[ 10 ] = n33; te[ 14 ] = n34;
  te[ 3 ] = n41; te[ 7 ] = n42; te[ 11 ] = n43; te[ 15 ] = n44;
  return this;
}

// gl-matrix 正好相反：mat4.fromValues(m00, m01, m02, m03, …) 的参数就按存储顺序给，
// m01 的意思是「第 0 列第 1 行」。同样传 1～16，两边存出来的数组互为转置。

数交给 GPU 时也按列主序：gl.uniformMatrix4fv(location, false, value)，第二个参数 transpose 在 WebGL 1 里必须是 false，value 按列主序（MDN）；项目就是这样传的（WebGL1Uniforms.ts:391）。GLSL 里 m[2] 取的是第 2 列。所以 shader 里写 uViewMatrix * vec4(position, 1.0)，算的就是数学上的 V · p，不用再转置。
