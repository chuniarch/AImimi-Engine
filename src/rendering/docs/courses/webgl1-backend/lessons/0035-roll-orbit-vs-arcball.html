歪头：轨道控制为什么不会，arcball 为什么会

你问「到底什么叫作歪头」。这一课先用一个滑块把歪头做出来，再给它一个可以计算的定义；然后证明项目的轨道控制「构造上」就算不出歪头，最后推出另一种旋转方式 arcball，看它为什么拖一圈回来头就歪了。

默认你已经会的：第 32 课的相机坐标（右、上、看向 −z）。用到的新数学有三样：旋转矩阵怎样作用在一个向量上、点积、叉积，都在用到的地方从头讲。
这一课讲的：相机的三根轴；歪头 (roll) 的定义和算法；轨道控制只记两个角，为什么右方向永远水平；arcball 怎样把鼠标位置变成旋转；为什么转动的先后顺序不能交换；两种控制并排拖一圈。

1. 相机的三根轴

第 32 课说，相机坐标的 x 指向画面右边，y 指向画面上边，相机看向 −z。把这三个方向放回世界里，就是相机的三根轴，用世界坐标表示：

  • 速查：相机控制的数学（第 32–35 课的公式和数字都在这一页）。
  • 右 r：画面右边在世界里指向哪；
  • 上 u：画面上边在世界里指向哪；
  • 后 b：相机背后的方向，看的方向 f = −b。

它们就是相机 world 矩阵的前三列（第 25 课）。HW2 的相机向下看了 11.31°：

r = (1, 0, 0)               画面右边 = 世界 +x，水平
u = (0, 0.9806, −0.1961)    画面上边：大部分朝世界 +y，往后仰了一点
b = (0, 0.1961, 0.9806)     看的方向 f = −b = (0, −0.1961, −0.9806)：往前、往下

2. 歪头是什么：先拖一个滑块

下面这台相机由三个滑块决定：方位角（绕世界竖轴转，左右环顾）、仰角（抬头低头），以及第三个「歪头」角：绕着自己的视线转。先只拖第三个：

你会看到，相机看的还是同一个点，目标点还在画面正中，可整个画面斜了：地面网格不再和画面中间那条水平虚线平行。这就像你把头歪向一边的肩膀。英文叫 roll（翻滚），飞机绕机身轴转动也叫这个名字。方位角和仰角分别叫 yaw、pitch（LearnOpenGL：Camera）。

3. 怎样判断歪没歪：右方向的 y 分量

「地面斜了」要变成一个能算的条件。没歪头时，画面的右边是水平的：右方向 r 不朝上也不朝下，r 的 y 分量是 0。歪了 ρ 度，r 就有一部分朝上了。所以：

没歪头  ⟺  r 的 y 分量 = 0
歪了多少：ρ = atan2(r 的 y 分量, u 的 y 分量)

atan2(a, b) 是「对边 a、邻边 b 的那个角」，和 tan 反过来用（第 32 课第 4 节）。拿一台平视的相机验证：歪头 10° 时，r = (cos 10°, sin 10°, 0) = (0.9848, 0.1736, 0)，u = (−0.1736, 0.9848, 0)，ρ = atan2(0.1736, 0.9848) = 10°。上面实验台的读数就是这样算的，你可以把歪头滑块拖到 10° 对照。相机同时还低着头时（比如 HW2 的 11.31°），这个算法照样给出歪头角，读数里可以验证：把仰角和歪头同时拖动，ρ 始终等于歪头滑块。

4. 轨道控制：只记两个角，所以不会歪

项目的轨道控制每次拖动，都从相机的位置重新算出两个角：方位角 az、仰角 el，加上拖动的增量，再把相机的旋转写成（mountOrbitCameraInput.ts:148–163）：

// 每次 pointermove 都这样做（节选；注释是课程加的）
const azimuth = (Math.atan2(x, z) + azimuthDelta) % TWO_PI      // 新的方位角
const elevation = clamp(Math.atan2(y, horizontal) + elevationDelta, // 新的仰角
  -MAX_ELEVATION, MAX_ELEVATION)
// …按 az、el 算出相机的新位置（:154–162）
// 第三个角永远是 0
camera.transform.setRotation([-elevation, azimuth, 0])

setRotation 的三个数是绕 x、y、z 轴转的角度。Transform 把它们合成一个旋转 R = R_z · R_y · R_x，第三个（绕 z，也就是绕视线）永远是 0，所以 R = R_y(az) · R_x(−el)。现在算右方向 r = R × (1, 0, 0)。从右往左，先算 R_x，再算 R_y。

R_x(α) 作用在 (1, 0, 0) 上。绕 x 轴转 α 的矩阵是：

        ⎡ 1     0       0    ⎤   ⎡ 1 ⎤   ⎡ 1 ⎤
R_x(α) =⎢ 0   cos α  −sin α  ⎥ × ⎢ 0 ⎥ = ⎢ 0 ⎥
        ⎣ 0   sin α   cos α  ⎦   ⎣ 0 ⎦   ⎣ 0 ⎦

矩阵乘一个向量，结果的第 i 个数 = 矩阵第 i 行和向量对应相乘再相加。向量是 (1, 0, 0)，所以结果就是矩阵的第一列 (1, 0, 0)。意思很直观：绕 x 轴转，x 轴本身不动。

R_y(β) 作用在 (1, 0, 0) 上。同样取第一列：

        ⎡  cos β   0   sin β ⎤   ⎡ 1 ⎤   ⎡  cos β ⎤
R_y(β) =⎢   0      1    0    ⎥ × ⎢ 0 ⎥ = ⎢   0    ⎥
        ⎣ −sin β   0   cos β ⎦   ⎣ 0 ⎦   ⎣ −sin β ⎦

所以 r = (cos az, 0, −sin az)：不管 az、el 是多少，r 的 y 分量都是 0。按第 3 节，ρ = 0。这就是「构造上不可能歪头」的意思：不是事后检查、再把歪头纠正回来，而是算 r 的式子里根本出不了非零的 y 分量。轨道控制记的只是两个角，拖一圈回到原来的 az、el，相机就回到一模一样的位置和朝向（第 7 节实测）。

5. arcball：用手抓住一个球

轨道控制把左右拖动和上下拖动拆成两个角。还有另一种想法，叫 arcball（Ken Shoemake 1992 年提出）：想象画面上浮着一个透明的球，你用鼠标按住球面上一点，拖到另一点，球就跟着手转过去，像用手拨地球仪。相机绕着目标点反向转，看起来就是场景跟着手转。要实现它，要解决两件事。

第一件：屏幕上的点怎样变成球面上的点。球心在画布中心，半径 R 取画布高的一半（600 px 高的画布，R = 300 px）。屏幕上一点离中心向右 sx、向上 sy 像素：

x = sx ÷ R，y = sy ÷ R          （变成以半径为单位）
如果 x² + y² ≤ 1：z = √(1 − x² − y²)   （按在球面上，球面方程 x² + y² + z² = 1）
否则：把 (x, y) 缩到长度 1，z = 0      （按在球外，就当按在球的边缘）

例子：按在中心，(x, y, z) = (0, 0, 1)；按在中心右边 100 px，x = 100/300 = 0.3333，z = √(1 − 0.1111) = 0.9428，点是 (0.3333, 0, 0.9428)。

第二件：球面上从 a 到 b，该绕哪根轴、转多少。两个工具：

  • 点积 a · b = a_x b_x + a_y b_y + a_z b_z。两个长度为 1 的向量，点积等于它们夹角的 cos。所以转角 θ = acos(a · b)。
  • 叉积 a × b = (a_y b_z − a_z b_y, a_z b_x − a_x b_z, a_x b_y − a_y b_x)，结果同时垂直于 a 和 b。从 a 转到 b，就绕这根轴转。
从中心向右拖 100 px：a = (0, 0, 1)，b = (0.3333, 0, 0.9428)
a · b = 0 + 0 + 1 × 0.9428 = 0.9428       θ = acos(0.9428) = 19.47°
a × b = (0 × 0.9428 − 1 × 0, 1 × 0.3333 − 0 × 0.9428, 0 − 0) = (0, 0.3333, 0)
转轴方向 (0, 1, 0)：画面的「上」方向。横着拖，就绕画面的竖轴转

从中心右边 200 px 拖到 300 px：a = (0.6667, 0, 0.7454)，b = (1, 0, 0)
a · b = 0.6667        θ = acos(0.6667) = 48.19°

同样拖 100 px，靠近中心转 19.47°，靠近边缘转 48.19°。这是 arcball 的手感：边缘「更灵敏」。轨道控制没有这个差别，每像素转的角度处处一样。

6. arcball 为什么会歪

关键在第 5 节那根转轴：它是在画面里算出来的。横着拖，转轴是画面的竖轴，也就是相机自己的上方向 u，而不是世界的竖轴 (0, 1, 0)。HW2 的相机低着头，u = (0, 0.9806, −0.1961) 是往后仰的（第 1 节）。绕一根歪着的轴转，原本水平的右方向 r 就被带离了水平面，r 的 y 分量不再是 0：只横着拖一次，就歪了。

反过来，轨道控制左右拖动时，绕的是世界的竖轴（只改方位角 az），r 始终在水平面里。

还有第二个原因：绕不同的轴转，先后顺序不同，结果就不同。拿一本书试试：先绕水平轴翻 90°、再绕竖轴转 90°，和反过来做，书最后的朝向不一样。用矩阵算（gl-matrix 实测）：

把 (0, 0, 1) 先绕 x 转 90°、再绕 y 转 90°：(0, −1, 0)
把 (0, 0, 1) 先绕 y 转 90°、再绕 x 转 90°：(1, 0, 0)

arcball 每次 pointermove 都在当前朝向上再乘一个新的小旋转，把所有旋转累积起来。拖一个闭合的正方形，四段的转轴各不相同，累积起来不等于「没转」，头就歪着回来了。轨道控制不累积旋转，每次都从两个角重新算，所以拖回原处就回到原样。

8. 对照 three.js

    
    
      
  • three.js 的 OrbitControls 和项目一样，只记球坐标的两个角，相机用 lookAt 加一个固定的「上」方向摆正，所以也不会歪头（本地 OrbitControls.js 的 update 一段）。
    • 
      
  • three.js 另外提供 TrackballControls 和 ArcballControls（本地 examples/jsm/controls/ 下都有）：它们允许自由旋转，也就允许歪头，适合看分子模型这类没有「地面」的东西。看场景、看人物，一般用 OrbitControls，因为地面斜了会让人头晕。
