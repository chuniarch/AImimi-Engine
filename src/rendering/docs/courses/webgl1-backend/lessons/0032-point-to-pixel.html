一个 3D 点，会画到屏幕的第几个像素

轨道控制的平移、滚轮缩放，背后都是同一条公式：给一个 3D 点，算出它画在画布的第几行、第几列。这一课从零推出这条公式。用到的数学只有直角三角形和 tan。每推一步，你都可以拖滑块验证，旁边同时显示「公式算出来的」和「项目的相机矩阵算出来的」两个数。

和你的目标的关系 —— 你问过：「横着移动为什么用高度 h，不用宽度 w」「近点、远点是在哪个空间里近、怎么才算近」「目标点 z = 0，哪来的深度」。这三个问题的答案都在这一课的公式里。后面三课（平移、滚轮、歪头）全部从这条公式推出来。
默认你已经会的：直角三角形；知道 3D 点可以写成 (x, y, z) 三个数。别的都从头讲，不要求记得第 25、26 课。
这一课讲的：世界坐标和相机坐标；深度；视场角和 tan；可见高度；1 个像素等于多少世界长度；点落在哪个像素的公式；横向为什么也用 h ÷ H；HW2 的相机低着头时，深度怎样算。
页面会用到：项目的 PerspectiveCamera（10 月 13 日打包的工作区版本），只做 CPU 计算，不用显卡。

1. 要回答的问题

HW2 的相机放在 (0, 20, 50)，看着 Mary 胸口的 (0, 10, 0)。画布宽 900 像素、高 600 像素，垂直视场角 45°。

  • 速查：相机控制的数学（第 32–35 课的公式和数字都在这一页）。
  • (0, 10, 0) 画在画布正中，第 450 列、第 300 行。这是相机「看着它」的意思。
  • 问题：它右边 5 个单位的点 (5, 10, 0)，画在第几列？

答案是第 521.02 列。这一课结束时，你能用笔算出这个数，并知道每一步为什么这样算。

2. 两套坐标：世界坐标和相机坐标

同一个点，可以用两套不同的坐标来描述。

  • 世界坐标 (world space)：整个场景共用的一套坐标。地面是 y = 0，Mary 站在原点附近。「相机在 (0, 20, 50)」「目标在 (0, 10, 0)」，说的都是世界坐标。它不随相机移动。
  • 相机坐标 (camera space，也叫 view space)：以相机自己为原点的坐标。规定：
    • x 轴指向画面的右边；
    • y 轴指向画面的上边；
    • 相机看向 −z 方向，也就是说，相机正前方的点，z 是负数。
    一个点的相机坐标 (x, y, z) 回答的是：从相机看过去，这个点在右边多少、上边多少、前面多远。相机一动，所有点的相机坐标都跟着变。

画面上的位置只取决于相机坐标：一个点在相机看来偏右多少、偏上多少，画面上就偏右多少、偏上多少。所以第一步，总是先把世界坐标换成相机坐标。

为了先把公式推出来，第 3–6 节用最简单的相机：放在世界原点、不旋转。这时两套坐标完全一样，世界坐标拿来就能用。第 7 节再回到 HW2 那台不在原点、还低着头的相机。

3. 深度 D

深度 (depth) 是一个点在相机正前方多远，记作 D。相机看向 −z，所以 D = −z（相机坐标里的 z）。

  • 点 (0, 0, −50)：在相机正前方 50 个单位，D = 50。
  • 点 (5, 3, −50)：偏右 5、偏上 3，可正前方的距离还是 50，D = 50。
  • 点 (0, 0, 10)：在相机背后，D = −10，画不出来。

要注意，深度不是「点到相机的直线距离」。点 (5, 3, −50) 到相机的直线距离是 √(5² + 3² + 50²) = 50.34，深度是 50。只有在视线正中间的点，两者才相等。下面所有公式用的都是深度。

4. 视场角和 tan：深度 D 处能看到多高

相机能看到的范围是一个向前张开的「锥」。从侧面看（下面的图），它是两条从相机出发的斜线，上下各张开一半的角度。上下两条线的夹角就是垂直视场角 fovY (field of view)。HW2 用 45°，所以视线上下各张开 22.5°。

在深度 D 处竖一块垂直于视线的板：板上能被看到的部分，就是这一深度处画面能装下的全部高度。它有多高？看视线以上那一半，是一个直角三角形：

  • 直角在视线和板的交点；
  • 沿着视线那条边（邻边）长 D；
  • 板上那条边（对边）就是要求的「半高」；
  • 相机那个角是 fovY / 2。

tan 的定义就是「对边 ÷ 邻边」：tan(fovY/2) = 半高 ÷ D。所以：

半高 = D × tan(fovY/2)
可见高度 h(D) = 2 × D × tan(fovY/2)

代入 HW2 的数：tan(22.5°) = 0.41421，意思是沿视线每往前走 1 个单位，上边界就升高 0.41421 个单位。D = 50.99 时，半高 = 50.99 × 0.41421 = 21.12，可见高度 h = 42.24。也就是说，在目标那么远的地方，画面从上到下能装下 42.24 个世界单位。

5. 换成像素

画布有 H = 600 行像素。在深度 D 处，这 600 行正好铺满可见高度 h(D)，所以：

深度 D 处：1 个像素 = h(D) ÷ H 个世界单位

D = 50.99 时，1 个像素 = 42.24 ÷ 600 = 0.0704 个世界单位。反过来说，1 个世界单位 = 600 ÷ 42.24 = 14.20 个像素。

现在算点画在哪一行。点在视线上方 y 个单位，换成像素就是 y ÷ (h/H) 个像素。画面中心是第 300 行；屏幕的行号向下增大，所以向上 y 要用减号。列也一样，中心是第 450 列，列号向右增大，用加号：

px = W/2 + x × H / h(D)        （第几列）
py = H/2 − y × H / h(D)        （第几行）
其中 h(D) = 2 × D × tan(fovY/2)          ★

第 1 节的问题：x = 5，D = 50.99，px = 450 + 5 × 600 ÷ 42.24 = 450 + 71.02 = 521.02。

下面拖三个滑块验证：读数先一步一步代入公式，最后一行用项目的 PerspectiveCamera 投影矩阵再算一遍（相机放在原点、不旋转，正是这一节假设的相机）。两个 py 应该一样。可以试试：

  • 把 y 拖到 21.12 附近，P 正好在上边界，py 接近 0。
  • 把 D 拖小，P 不动，py 往上跑；拖大，py 往中心靠。
  • 把 fovY 拖大，同一个 P 离中心更近：视场角大，同一个高度占的像素少。

6. 横向为什么也用 h ÷ H

★ 的第一行，横向的 px 也是 x × H / h(D)，分母里是高度 h、画布高 H，没有宽度 W。这是你问过的问题。原因是：横纵两个方向「1 个像素等于多少世界单位」，算出来完全相等。

  1. 项目把相机的宽高比 aspect 设成画布的宽高比：aspect = W ÷ H = 900 ÷ 600 = 1.5（PerspectiveCamera 的 aspect 参数；画布大小一变，Engine 就用 drawing buffer 的宽 ÷ 高重设它，engine.ts:431–435）。
  2. 投影矩阵规定：可见宽度 w = aspect × 可见高度 h。D = 50.99 时，w = 1.5 × 42.24 = 63.36。
  3. 这 63.36 个单位铺满 W = 900 列：横向 1 个像素 = 63.36 ÷ 900 = 0.0704 个单位。
  4. 纵向 1 个像素 = 42.24 ÷ 600 = 0.0704 个单位。两个数相同。

用字母写：w ÷ W = (W/H × h) ÷ W = h ÷ H，W 被约掉了。在几何上，这就是「像素是正方形的」：一个像素横着、竖着代表同样长的世界距离。所以横向用 h/H 不是写错，它和 w/W 本来就是同一个数。三维软件通常只用高度来换算，three.js 的 OrbitControls 也写了注释：只用 clientHeight，宽高比就不会让速度变形（本地文件 OrbitControls.js:908）。

只有一种情况两者不同：相机的 aspect 和画布的 W/H 不一样，画面被横向拉伸或压扁了（比如画布变宽了，却忘了更新相机）。这时像素不再是正方形，横向就要改用 w/W。

7. 回到 HW2：相机低着头时，深度怎样算

HW2 的相机不在原点，还低着头（从 (0, 20, 50) 看向 (0, 10, 0)，向下 11.3°）。这时世界坐标不能直接代进 ★，要先换成相机坐标。下面这张侧视图，从世界的 +x 方向看过去：横轴是世界 z，竖轴是世界 y。

这张图回答了「目标点 z = 0，哪来的深度」：z = 0 是世界坐标，说的是它在世界的哪里；深度是相机坐标里的量，说的是它在相机正前方多远。两者是不同坐标系里的数，没有理由相等。

深度怎样算？先求视线方向的单位向量（长度为 1 的方向）f：

目标 − 相机 = (0, 10, 0) − (0, 20, 50) = (0, −10, −50)
长度 = √(0² + 10² + 50²) = √2600 = 50.99
f = (0, −10, −50) ÷ 50.99 = (0, −0.1961, −0.9806)

一个点 P 的深度，就是从相机到 P 的向量在 f 方向上「走了多远」，用点积 (dot product) 算：两个向量对应分量相乘再相加。

D = (P − 相机) · f

近点 (0, 20, 30)：P − 相机 = (0, 0, −20)
D = 0 × 0 + 0 × (−0.1961) + (−20) × (−0.9806) = 19.61

远点 (0, 0, −50)：P − 相机 = (0, −20, −100)
D = 0 + (−20) × (−0.1961) + (−100) × (−0.9806) = 3.92 + 98.06 = 101.98

这就是我上一轮说的「近点」「远点」：近指深度小（在相机和目标之间），远指深度大（在目标后面）。近点到相机的直线距离是 20，深度是 19.61，又一次说明这两者不是一回事。

同样的道理，x、y 也要沿着相机自己的右方向、上方向量（同样是点积）。项目里不用一个个点积去算：相机的 world 矩阵求逆就是 view 矩阵（第 25 课），乘一次就把世界坐标换成了相机坐标。下面的卡片用项目的相机矩阵算四个点，再拿相机坐标代进 ★：

8. 近大远小

把 ★ 换个角度读：同样 5 个世界单位长的东西，在屏幕上占 5 × H / h(D) 个像素。h(D) 和 D 成正比，所以占的像素和 D 成反比：

D = 19.61（近点那么远）：5 × 600 ÷ 16.25 = 184.65 px
D = 50.99（目标那么远）：5 × 600 ÷ 42.24 =  71.02 px
D = 101.98（远点那么远）：5 × 600 ÷ 84.48 =  35.51 px

深度翻倍（50.99 → 101.98），像素减半（71.02 → 35.51）。这就是透视的「近大远小」。下一课的平移，就是这个「反比」造成的：同样挪动相机，近处的东西在屏幕上挪得多，远处的挪得少。
