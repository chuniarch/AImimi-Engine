轨道控制：拖动怎样变成相机的新位置

第 25 课推出了相机的三样东西：world 矩阵 C（四列是右、上、后和位置 eye）、V = C⁻¹、投影矩阵 P，还推出了用方位角 az、仰角 el 记下朝向的写法 rotation = [−el, az, 0]。轨道控制要做的，就是每次拖动以后算出新的 eye 和新的 [−el, az, 0]。这一课先和 three.js 的 OrbitControls 并排拖一拖，再一版一版写出 mountOrbitCameraInput：控制器怎样记状态、两极怎样处理、滚轮怎样缩放、浏览器事件怎样接、谁来重画。

和你的目标的关系 —— HW2 换到新渲染路径以后，three.js 的 OrbitControls 就被关掉了（engine.ts:205），转动视角全靠这个文件。FFT 海面要绕着看，也会用它；以后要加阻尼，就是在这里改（右键平移已经在课后加上了，见 3.6 节）。
默认你已经会的：第 25 课的 C、V、P，offset = eye − target，az = atan2(dx, dz)、el = atan2(dy, horizontal) 和 rotation = [−el, az, 0]；第 8 课 Transform 的 version；第 23 课讲过，removeEventListener 要传同一个函数对象。
这一课从零讲的：球坐标的读和写；控制器为什么不能自己记角度；两极为什么要留余量、为什么留 0.001；滚轮为什么用乘法；pointer 事件、pointer capture、touch-action、passive；「当前相机」与拖到一半换相机；挂载前先验证、幂等卸载；为什么不需要 OrbitControls 那样的 update()。

0. 先拖一拖

左边是项目代码，右边是 three.js r177 原版。两边的初始位置都是 HW2 的 [0, 20, 50]，都绕 [0, 10, 0] 转，距离都限制在 1～300（左边的配置抄自 setup.ts:124–128）。按住左键拖动，或者滚动滚轮；下面的按钮会给两边发同样的事件。

先留意三件事，后面几节逐一解释：

  1. 同样拖，两边的 position 读数一样（第 2 节）。
  2. 滚一格，两边的距离不一样（2.7 节）。
  3. 两边的 rotation 读数完全不同，画面却一样（第 25 课 5.2 节）。

按钮发的是合成事件。合成事件没有真实的指针，所以发事件的那一瞬间，把 canvas 的 setPointerCapture 换成只记账的版本，发完就恢复。用鼠标拖的时候，用的是浏览器真实的 pointer capture。勾上「打开阻尼」以后，在右边拖一下再松手，画面还会接着滑一会儿：OrbitControls 在每帧的 update() 里把剩下的角度一点点用完（第 4 节）。左边没有这个功能。

1.3 一块画布，两套控制

2. 一次拖动怎样变成新位置

2.1 球坐标：三个数描述「绕着目标的哪里」

相机位置 eye = target + offset。offset 可以用三个数描述：距离 distance、方位角 az、仰角 el。第 25 课 5.2 节用 az、el 算出了相机的 rotation；轨道控制还要反过来，由三个数算出 eye。两个方向的换算： 

// 例：HW2 初始，偏移 = [0, 20, 50] − [0, 10, 0] = [0, 10, 50]

// 直角 → 球（读）
horizontal = Math.hypot(x, z)               // 50：水平面上离目标多远
distance = Math.hypot(horizontal, y)        // 50.99
az = Math.atan2(x, z)                       // 0
el = Math.atan2(y, horizontal)              // 0.1974 rad = 11.31°

// 球 → 直角（写）
ring = distance * Math.cos(el)              // 水平那一圈的半径
x = ring * Math.sin(az), y = distance * Math.sin(el), z = ring * Math.cos(az)

拖动只是在 az、el 上加减，滚轮只是把 distance 乘上一个倍数。three.js 的 Spherical 也用这三个数，只是竖直方向量的是 phi：从 +Y 往下量，phi = 90° − el；theta = atan2(x, z)，和这里的方位角一样（Spherical.js:114–126）。

2.2 第 1 版：控制器自己记住三个角

最直接的写法：挂载时把相机位置换成三个角，以后每次拖动就在角上加减，再换回位置。

// 第 1 版：控制器自己记住三个数，每次拖动在这三个数上加减，然后改相机的位置
function createOrbitV1(target: Vec3Tuple, firstCamera: OrbitCamera): OrbitVersion {
  // 挂载时读一次相机位置，换成球坐标。HW2 的初始相机在 [0, 20, 50]，目标是 [0, 10, 0]：
  const p = firstCamera.transform.position
  const x = p[0] - target[0] // 0
  const y = p[1] - target[1] // 10
  const z = p[2] - target[2] // 50
  const radius = Math.hypot(x, y, z) // 50.99：到目标的距离
  let azimuth = Math.atan2(x, z) // 0：水平面上，从 +Z 方向转过的角（方位角）
  let elevation = Math.atan2(y, Math.hypot(x, z)) // 0.1974 rad = 11.31°：高出水平面的角（仰角）

  return {
    drag(camera, dx, dy, canvasHeight) {
      // 拖满一个 canvas 高度 = 转一整圈 2π；600 px 高的 canvas，拖 150 px 转 90°
      const radiansPerPixel = (2 * Math.PI) / canvasHeight
      azimuth -= dx * radiansPerPixel // 向右拖：方位角变小
      elevation += dy * radiansPerPixel // 向下拖：仰角变大，相机升高

      // 球坐标 → 直角坐标：高度是 r·sin(仰角)；水平那一圈的半径是 r·cos(仰角)，
      // 再按方位角分到 x（sin）和 z（cos）上
      const ring = radius * Math.cos(elevation)
      camera.transform.setPosition([
        target[0] + ring * Math.sin(azimuth),
        target[1] + radius * Math.sin(elevation),
        target[2] + ring * Math.cos(azimuth)
      ])
      // 只改了位置，相机的朝向 rotation 还是挂载前的样子
    }
  }
}

2.3 第 2 版：再让相机转头

按第 25 课 5.2 节，补上一行 setRotation。目标回到了画面中央。可 HW2 还有一个情况：切换预设时，HW2SceneController 会建一个新 Scene、一台新 Camera（createHW2Scene.ts:373–382），位置又是 [0, 20, 50]。

// 第 2 版：在第 1 版上加一行，让相机转头看向目标
function createOrbitV2(target: Vec3Tuple, firstCamera: OrbitCamera): OrbitVersion {
  const p = firstCamera.transform.position
  const x = p[0] - target[0]
  const y = p[1] - target[1]
  const z = p[2] - target[2]
  const radius = Math.hypot(x, y, z)
  let azimuth = Math.atan2(x, z) // 只在挂载时从 firstCamera 读这一次
  let elevation = Math.atan2(y, Math.hypot(x, z))

  return {
    drag(camera, dx, dy, canvasHeight) {
      const radiansPerPixel = (2 * Math.PI) / canvasHeight
      azimuth -= dx * radiansPerPixel
      elevation += dy * radiansPerPixel
      const ring = radius * Math.cos(elevation)
      camera.transform.setPosition([
        target[0] + ring * Math.sin(azimuth),
        target[1] + radius * Math.sin(elevation),
        target[2] + ring * Math.cos(azimuth)
      ])
      // 新增：先绕 X 低头 elevation，再绕 Y 转 azimuth（第 25 课 5.2 节）
      camera.transform.setRotation([-elevation, azimuth, 0])
    }
  }
}

2.4 第 3 版：每次都从相机现在的位置重新算

问题出在控制器自己存了一份角度，而相机的真实位置会被别人改：换预设、工厂设初始取景、以后还可能有动画。第 3 版不存角度，每次拖动都先读相机现在的位置。three.js 也是这样做的：update() 一开头就从 camera.position 重新算出 spherical（OrbitControls.js:597–607），所以它的文档说，手动改过相机位置以后调用一次 update() 就行（:71–73）。 

// 第 3 版：控制器不记角度。每次拖动都从相机「现在」的位置重新算
function createOrbitV3(target: Vec3Tuple): OrbitVersion {
  return {
    drag(camera, dx, dy, canvasHeight) {
      // 现在的位置：也许刚换了一台新相机，也许被别的代码改过，都以它为准
      const p = camera.transform.position
      const x = p[0] - target[0]
      const y = p[1] - target[1]
      const z = p[2] - target[2]
      const horizontal = Math.hypot(x, z) // 在水平面上离目标多远
      const radius = Math.hypot(horizontal, y)

      const radiansPerPixel = (2 * Math.PI) / canvasHeight
      const azimuth = Math.atan2(x, z) - dx * radiansPerPixel
      const elevation = Math.atan2(y, horizontal) + dy * radiansPerPixel // 还没有上下限

      const ring = radius * Math.cos(elevation)
      camera.transform.setPosition([
        target[0] + ring * Math.sin(azimuth),
        target[1] + radius * Math.sin(elevation),
        target[2] + ring * Math.cos(azimuth)
      ])
      camera.transform.setRotation([-elevation, azimuth, 0])
    }
  }
}

2.5 真实代码：再加上下限和两道检查

真实的 applyOrbit 比第 3 版多了三样：仰角有上下限；相机正好在目标上时有退路；写进 Transform 之前查一次 Float32。滚轮也用它（参数 zoom）。

// mountOrbitCameraInput.ts:36–38、:132–164（注释是课程加的）
// minDistance、maxDistance 是挂载时从 options 复制的（:67–68）
const TWO_PI = 2 * Math.PI
// 仰角的上下限：离正上方、正下方各留 0.001 rad（约 0.057°）
const MAX_ELEVATION = Math.PI / 2 - 0.001

function applyOrbit(
  camera: Camera,
  azimuthDelta: number, // 这一次加多少方位角（弧度）
  elevationDelta: number, // 这一次加多少仰角（弧度）
  zoom: number // 距离乘上几倍；拖动时传 1
): void {
  // 目标点：这台相机平移过就用它自己的，否则用挂载时复制的 initialTarget（:66）
  // 这一行是 10 月 8 日课后加的，配合右键平移（3.6 节）
  const target = targets.get(camera) ?? initialTarget
  // ① 读：相机现在在哪（第 3 版的做法）
  const position = camera.transform.position
  const x = position[0] - target[0]
  const y = position[1] - target[1]
  const z = position[2] - target[2]
  const horizontal = Math.hypot(x, z)
  const distance = Math.hypot(horizontal, y)
  if (!Number.isFinite(distance)) return // 位置里已经有 NaN 或 Infinity：什么都不写

  // ② 算：新的距离、方位角、仰角
  // 相机正好在目标上时 distance 是 0，0 乘几倍都是 0，所以改用 minDistance
  const radius = clamp((distance || minDistance) * zoom, minDistance, maxDistance)
  const azimuth = (Math.atan2(x, z) + azimuthDelta) % TWO_PI // % 只是不让数越转越大
  const elevation = clamp(
    Math.atan2(y, horizontal) + elevationDelta,
    -MAX_ELEVATION, // 新增：仰角有上下限
    MAX_ELEVATION
  )

  // ③ 球坐标 → 直角坐标（和前三版同一组公式）
  const ringRadius = radius * Math.cos(elevation)
  const next: Vec3Tuple = [
    target[0] + ringRadius * Math.sin(azimuth),
    target[1] + radius * Math.sin(elevation),
    target[2] + ringRadius * Math.cos(azimuth)
  ]
  // ④ 写之前再查：Transform 按 Float32 存，3.5e38 存进去就成了 Infinity（第 8 课）
  if (!next.every((value) => Number.isFinite(Math.fround(value)))) return
  camera.transform.setPosition(next)
  camera.transform.setRotation([-elevation, azimuth, 0]) // 第 25 课 5.2 节：先低头，再转身
}

上下限为什么离 90° 留 0.001 rad，而 three.js 只留 10−6（Spherical.js:84–88）？上面第二张卡片给出了原因：本项目的 Transform 按 Float32 存位置，three.js 的 Vector3 用的是 JS 的 Float64。离头顶越近，偏移的水平分量越小，小到比目标坐标的 Float32 精度还小时，加到目标坐标上就被舍掉了，下一次就读不出方位角。代码注释只写了「保持确定的水平朝向」，没有点明 Float32，这是我按实测推出来的。

2.6 速度和方向：和 three.js 一模一样

每像素转多少：2π × rotateSpeed ÷ canvas 的 CSS 高度（mountOrbitCameraInput.ts:276）。three.js 用的是同一个式子，连「用高度、不用宽度」都一样，源码里还特意注了一句「yes, height」（OrbitControls.js:1018–1020）。用高度，宽屏和竖屏的手感就一样；用 CSS 像素而不用 drawing buffer 的像素，DPR 为 2 的屏幕上也不会转得快一倍。

方向也一样：向右拖，方位角变小（three.js 的 _rotateLeft 是 theta 减去角度，:853–863）；向下拖，仰角变大，相机升高。我在 Node 里用同一串事件分别驱动两边（canvas 高 600 px）：

依次做本项目的 positionthree.js 的 position
向右拖 150 px[−50.0000, 20.0000, 0.0000][−50.0000, 20.0000, 0.0000]
再向下拖 100 px[−16.3397, 58.3013, 0.0000][−16.3397, 58.3013, 0.0000]
再向上拖 600 px（撞到下限）[−0.0510, −40.9902, 0.0000][−0.0001, −40.9902, 0.0000]

前两行到小数点后 4 位都一样。第三行的差别只来自两边上下限留的余量不同（0.001 和 10−6）。第 5 节有一个自由组合，可以在你的浏览器里重跑。

2.7 滚轮：乘法，不是加法

// mountOrbitCameraInput.ts:296–306（注释是课程加的）
function onWheel(event: WheelEvent): void {
  if (closed || !Number.isFinite(event.deltaY) || event.deltaY === 0) return
  const camera = getCamera()
  if (camera === null) return // 场景还没装好，或者已经离开 HW2
  if (drag !== null && camera !== drag.camera) endDrag() // 拖着拖着换了相机：旧手势作废
  // deltaY 的单位看 deltaMode：0 是像素；1 是行，按 16 px 算；2 是页，按 canvas 高度算
  const unit =
    event.deltaMode === 1 ? 16 : event.deltaMode === 2 ? Math.max(1, canvas.clientHeight) : 1
  // 指数缩放：deltaY = 100 时 e^0.1 = ×1.105；反方向一格 e^−0.1 = ×0.905，正好抵消
  const zoom = Math.exp(clamp(event.deltaY * unit * zoomSpeed, -50, 50))
  applyOrbit(camera, 0, 0, zoom)
  event.preventDefault() // 不让页面跟着滚。要生效，注册时就得写 passive: false
}

three.js 也是乘法，只是底数不同：一格的倍数是 0.950.01 × |deltaY| × zoomSpeed（OrbitControls.js:846–851）。deltaY = 100 时是 ×1.0526，本项目是 ×1.1052，所以 §0 里滚一格两边的距离不一样。按指数换算，three.js 的 zoomSpeed = 1 相当于这里的 zoomSpeed = 0.000513。deltaMode 的处理也有一处不同：一页，three.js 按 100 px 算，这里按 canvas 高度算；另外 three.js 把按着 Ctrl 的滚轮（触控板捏合）放大 10 倍（:1417–1446），这里没有。

3. 输入事件

3.1 pointer 事件速成

鼠标、手指、手写笔都发同一套事件：按下 pointerdown → 移动若干次 pointermove → 松开 pointerup，或者被浏览器收走 pointercancel。代码读了事件上的这几个字段：

字段含义这里怎么用
pointerId每个指针一个号码；每根手指各一个只认按下的那一个（:257）
isPrimary是不是主指针：鼠标、第一根手指第二根手指不开始拖动（:234）
button这次是哪个键变了：0 左键，2 右键左键（单指）开始旋转；鼠标右键开始平移（:235–241，3.6 节）；别的键不管
buttons此刻按着哪些键，按位记：左键是 1，右键是 2移动时，开始这次拖动的那个键已经不在（旋转看左键，平移看右键），说明 pointerup 丢了（:260–267）
clientX / clientY指针位置，单位是 CSS 像素算 dx、dy（:268–269）
pointerType'mouse'、'touch'、'pen'buttons 的检查只对鼠标做（:263）；平移只认鼠标右键（:238）

另外三个浏览器机制：

  • pointer capture：setPointerCapture(id) 以后，这个指针的事件都改送到这个元素，直到 pointerup 或 releasePointerCapture；pointerId 不是一个活着的指针时抛 NotFoundError（MDN）。没有它，拖出 canvas 以后 pointermove 就送到别的元素去了，在外面松手也收不到。
  • touch-action: none：浏览器不再拿触摸手势去滚动、缩放页面。不设的话，浏览器一接手这个触摸，就给你发 pointercancel（MDN touch-action）。
  • passive: false：只有非被动的监听里，preventDefault 才有效。wheel 监听挂在 window、document、documentElement、body 上时默认是被动的，挂在 canvas 上默认不是（MDN addEventListener）。这里明写 passive: false，读代码的人一眼就知道这个监听会 preventDefault。

3.2 一次拖动的记录

// mountOrbitCameraInput.ts:27–34、:233–284、:108–119（注释是课程加的）
interface DragState {
  readonly pointerId: number // 哪个指针：鼠标、哪根手指
  readonly camera: Camera // 按下那一刻的相机
  readonly mode: 'rotate' | 'pan' // 课后新增：这次是旋转还是平移，中途按别的键也不换
  x: number // 上一个事件的 clientX（CSS 像素）
  y: number
}

function onPointerDown(event: PointerEvent): void {
  // 已经卸载、已经在拖、不是主指针（第二根手指）：都不管
  if (closed || drag !== null || !event.isPrimary) return
  // 左键（或单指）旋转；鼠标右键平移；别的键不管
  const mode =
    event.button === 0
      ? 'rotate'
      : event.button === 2 && event.pointerType === 'mouse'
        ? 'pan'
        : null
  if (mode === null) return
  const camera = getCamera()
  if (camera === null) return
  // 平移只支持透视相机；panSpeed 为 0 表示关掉平移
  if (mode === 'pan' && (!(camera instanceof PerspectiveCamera) || panSpeed === 0)) return
  try {
    canvas.setPointerCapture(event.pointerId) // 之后这个指针的事件都送到 canvas，拖出画布也一样
  } catch {
    return // 指针已失效，或 canvas 已不在文档里：不开始一个结束不了的手势
  }
  drag = { pointerId: event.pointerId, camera, mode, x: event.clientX, y: event.clientY }
  event.preventDefault()
}

function onPointerMove(event: PointerEvent): void {
  if (closed || event.pointerId !== drag?.pointerId) return // 不是这次拖动的指针
  const camera = getCamera()
  // buttons 按位记：左键 1、右键 2。旋转要左键还按着，平移要右键还按着
  const requiredButtons = drag.mode === 'pan' ? 2 : 1
  // 相机已经换了；或者那个键其实早就松开了（pointerup 没送到这里）：结束这次拖动
  if (
    camera !== drag.camera ||
    (event.pointerType === 'mouse' && (event.buttons & requiredButtons) === 0)
  ) {
    endDrag()
    return
  }
  const dx = event.clientX - drag.x // 和上一个事件比，不是和按下时比
  const dy = event.clientY - drag.y
  drag.x = event.clientX
  drag.y = event.clientY
  if (!Number.isFinite(dx) || !Number.isFinite(dy) || (dx === 0 && dy === 0)) return
  if (drag.mode === 'pan') {
    applyPan(camera, dx, dy) // 3.6 节
  } else {
    // 用 CSS 高度，不用 drawing buffer 的像素：高 DPR 屏幕上手感不变
    const radiansPerPixel = (TWO_PI * rotateSpeed) / Math.max(1, canvas.clientHeight)
    applyOrbit(camera, -dx * radiansPerPixel, dy * radiansPerPixel, 1)
  }
  event.preventDefault()
}

function onPointerEnd(event: PointerEvent): void {
  // pointerup、pointercancel、lostpointercapture 共用这一个函数
  if (event.pointerId === drag?.pointerId) endDrag()
}

function endDrag(): void {
  const previous = drag
  drag = null // 先清空。即使下面引发 lostpointercapture 又进到这里，也只看到 null
  if (previous === null) return
  try {
    if (canvas.hasPointerCapture(previous.pointerId)) {
      canvas.releasePointerCapture(previous.pointerId)
    }
  } catch {
    // 指针已经失效：本地手势照样算结束，不再留着旧 Camera 的引用
  }
}

注意 dx 是和上一个事件比，不是和按下时比。每个 pointermove 都在相机现在的位置上再转一小步，配合第 3 版「每次重新读位置」，中途有人改了相机也不会跳。

3.4 什么时候结束一次拖动

发生了什么为什么要结束
pointerup正常松手
pointercancel浏览器收走了这个指针，比如触摸被拿去滚动页面
lostpointercapture捕获被别的元素拿走，或者被浏览器撤销
window 的 blur切到别的窗口以后，松手事件可能根本送不到页面
webglcontextlost画面已经没了，手势不该延续到恢复以后
pointermove 时 buttons 里没有开始拖动的那个键（旋转看左键，平移看右键）在别处松了手，pointerup 丢了
pointermove 时相机换了旧相机已经不归这次拖动管
卸载不再留着任何相机的引用

endDrag 先把 drag 设成 null，再交还捕获。交还时浏览器可能派发 lostpointercapture，又一次调进 onPointerEnd → endDrag；那时 drag 已经是 null，直接返回，不会交还两次。

3.6 课后新增：右键平移

10 月 12 日补：这一课写完以后（10 月 8 日下午），你给 mountOrbitCameraInput 加了右键平移。上面各节的节选和行号已经换成现在的代码；第 0 节和各张卡片用的包也重新打过，跑的是带平移的版本。这一节只讲新增的部分。

需求。旋转和缩放都绕着同一个目标点 target。想看 Mary 的手、看地板的一角，就得把这个点挪过去。平移要做的事：相机和 target 一起，沿着屏幕的「右」和「上」挪同样的距离。两者之差不变，所以朝向、距离都不变，画面像被手拖着走。

拖 1 像素该挪多远。目标在相机前方 d 处时，那个距离上能看见的高度是 2 × d × tan(fovY / 2)，它铺满 canvas 的 CSS 高度。用 HW2 的初始值算：相机在 [0, 20, 50]，target 在 [0, 10, 0]，d = √(10² + 50²) = 50.9902；fovY = π/4，可见高度 = 2 × 50.9902 × tan(π/8) = 42.2417。canvas 高 600 px、panSpeed = 0.8 时，每像素挪 42.2417 × 0.8 ÷ 600 = 0.05632。横竖用同一个比例，不再乘 aspect。 

// mountOrbitCameraInput.ts:184–230（节选；注释是课程加的）
function applyPan(camera: Camera, dx: number, dy: number): void {
  // 要用 fovY，所以只支持透视相机
  if (!(camera instanceof PerspectiveCamera) || panSpeed === 0) return
  const target = targets.get(camera) ?? initialTarget
  const position = camera.transform.position
  const distance = Math.hypot(
    position[0] - target[0],
    position[1] - target[1],
    position[2] - target[2]
  )
  // 每像素挪多远：可见高度 × panSpeed ÷ canvas 的 CSS 高度
  const unitsPerPixel =
    (2 * distance * Math.tan(camera.fovY / 2) * panSpeed) / Math.max(1, canvas.clientHeight)
  if (!Number.isFinite(unitsPerPixel) || unitsPerPixel === 0) return

  // 局部矩阵的第 0 列是相机的「右」，第 1 列是相机的「上」（第 25 课）
  camera.transform.copyLocalMatrixTo(panLocalMatrix)
  const rightLength = Math.hypot(panLocalMatrix[0]!, panLocalMatrix[1]!, panLocalMatrix[2]!)
  const upLength = Math.hypot(panLocalMatrix[4]!, panLocalMatrix[5]!, panLocalMatrix[6]!)
  // …（省略：长度不是有限正数就返回，:200–206）

  // 鼠标向右（dx > 0）→ 相机向左挪，画面里的东西跟着鼠标向右走；向下同理
  const horizontal = (-dx * unitsPerPixel) / rightLength
  const vertical = (dy * unitsPerPixel) / upLength
  // 先算出真正会写进 Transform 的 Float32 位置
  const nextPosition: Vec3Tuple = [
    Math.fround(
      position[0] + horizontal * panLocalMatrix[0]! + vertical * panLocalMatrix[4]!
    ),
    Math.fround(
      position[1] + horizontal * panLocalMatrix[1]! + vertical * panLocalMatrix[5]!
    ),
    Math.fround(
      position[2] + horizontal * panLocalMatrix[2]! + vertical * panLocalMatrix[6]!
    )
  ]
  // target 跟着「实际挪了多少」走：被 Float32 舍掉的微小拖动，target 也不动
  const nextTarget: Vec3Tuple = [
    target[0] + (nextPosition[0] - position[0]),
    target[1] + (nextPosition[1] - position[1]),
    target[2] + (nextPosition[2] - position[2])
  ]
  // …（省略：两者都是有限数才提交，:222–226）
  camera.transform.setPosition(nextPosition)
  targets.set(camera, nextTarget)       // 这台相机从此用自己的 target
}

target 存在哪一个 WeakMap<Camera, Vec3Tuple>（:93–100）。只有平移过的相机才有记录；预设切换造出的新相机查不到，就用挂载时复制的 initialTarget，不会继承旧相机的偏移。WeakMap 不拦着退出的相机被回收。

4. 谁来重画：为什么没有 update()

three.js 的 OrbitControls 有一个 update()：拖动的处理函数里会调用它（OrbitControls.js:1024），由它改位置、lookAt、移动超过阈值时派发 change 事件（:813–818，给「有变化才重画」的页面用）。打开阻尼或自动旋转时，还必须在每帧调用一次（:77）。旧路径的 Engine 就是每帧先 cameraControls.update() 再画（engine.ts:533）。

项目的控制器没有 update()：事件里直接写 Transform，Engine 本来就有一条 rAF 链，下一帧照常画（mountOrbitCameraInput.ts:59：「不引入第二条 rAF 链」）。HW2 路径的 Engine.update 是空的（engine.ts:282–289）。代价是没有阻尼：要加的话，需要一个每帧都会被调用的地方，把剩下的角度一点点用掉，而现在 HW2 路径上还没有这样的地方。
