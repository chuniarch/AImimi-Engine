平移：拖 100 像素，相机该挪多少

右键拖动画面，相机跟着平移。这一课只回答两个问题：相机该挪多远？为什么一拖动，近处的东西比你的手挪得快，远处的比手挪得慢？两个答案都从第 32 课那条公式 ★ 推出来。

默认你已经会的：第 32 课的 ★（点落在哪个像素），以及「深度 D」是相机正前方多远。
这一课讲的：相机挪和点挪是同一件事的两面；为什么只有一个深度能跟手；挪多少的公式；项目的 applyPan 逐行读；在画布上亲手拖动验证。

1. 要回答的问题

HW2 的相机在 (0, 20, 50)，看着目标 (0, 10, 0)，画布高 600 像素。你按住右键，向右拖了 100 像素。

  • 速查：相机控制的数学（第 32–35 课的公式和数字都在这一页）。
  • 你想要的效果：像用手按住一张照片往右拖，手底下的东西跟着手走。
  • 要算的：相机该往哪个方向、挪多远。

2. 相机向左挪，点就向右挪

先看一维的例子。一条数轴上，相机在 0，一个点在 3。从相机看，点在右边 3。现在相机向左挪到 −2，点不动：从相机看，点在右边 5。

相机向左挪 2，点在相机看来就向右挪了 2。三维也一样：相机沿着自己的「右」方向挪 −s（向左 s），每个点的相机坐标 x 都增加 s。

还有一件事：相机这次是横着挪的，挪动方向和视线垂直，没有往前也没有往后。所以每个点的深度 D 都不变。

所以在相机坐标里，平移前后的变化只有一处：

平移前：点的相机坐标 (x,     y, −D)
平移后：点的相机坐标 (x + s, y, −D)      （相机向左挪了 s）

3. 代入 ★：挪的像素和深度有关

第 32 课的 ★：px = W/2 + x × H / h(D)，其中 h(D) = 2 × D × tan(fovY/2)。平移前后，只有 x 变了，D 没变，所以列号的变化是：

Δpx = (x + s) × H / h(D) − x × H / h(D)
    = s × H / h(D)

s 是同一个数（相机只挪了一次），可 h(D) 和 D 成正比。所以：深度越小的点，在屏幕上挪得越多。同一次平移，不可能让所有点都正好挪 100 像素。这就是「近处的东西比手挪得快」的原因，叫视差 (parallax)。坐车时，路边的护栏飞快后退，远处的山几乎不动，是同一个道理。

4. 让目标点跟手：相机挪多少

既然只能让某一个深度正好跟手，就要选一个。项目选的是目标点所在的深度，记作 d。理由：

  • 相机一直看着目标点，它在画面正中，通常也是你眼睛盯着的地方；
  • 左键旋转时，相机绕的也是这个点。拖完以后，它还在你手底下。

要求「目标点挪了 dx 像素」，代入第 3 节：

s × H / h(d) = dx
⟹ s = dx × h(d) / H

右边的 h(d) / H，就是第 32 课第 5 节的「深度 d 处 1 个像素等于多少世界单位」。拖 1 像素挪这么多单位，拖 dx 像素挪 dx 倍。代入 HW2 的数：

d = 50.99（相机到目标点的距离；目标在视线正中，所以距离就是深度）
h(d) = 2 × 50.99 × tan(22.5°) = 42.24
h(d) / H = 42.24 ÷ 600 = 0.0704
s = 100 × 0.0704 = 7.04          相机向左挪 7.04 个世界单位

HW2 实际挂载时传了 panSpeed: 0.8（setup.ts:127），相机挪 7.04 × 0.8 = 5.63，目标点挪 80 像素，比手慢一点。下面的实验台用 panSpeed 1，目标点正好跟手。

5. 其他深度挪多少：视差

把 s = dx × h(d) / H 代回第 3 节的 Δpx = s × H / h(D)：

Δpx = dx × h(d) / H × H / h(D)
    = dx × h(d) / h(D)
    = dx × d / D            （h 和深度成正比，2 × tan(fovY/2) 约掉了）

深度为 D 的点，挪的像素是手的 d / D 倍。三个点（深度见第 32 课第 7 节）：

目标点 D = 50.99：  100 × 50.99 ÷ 50.99  = 100 像素（正好跟手）
近点   D = 19.61：  100 × 50.99 ÷ 19.61  = 260 像素（比手快 2.6 倍）
远点   D = 101.98： 100 × 50.99 ÷ 101.98 =  50 像素（只有手的一半）

这就是我上一轮那张表想说的事。表里的「近点」「远点」，指的是深度小于、大于目标点的点。

6. 亲手拖一下

下面是项目真实的 PerspectiveCamera 加 mountOrbitCameraInput（panSpeed 1），画的是地面网格、一个代表 Mary 的方盒，和三个标记点。为了在画面上不叠在一起，近点、远点各往旁边挪了 6 个单位，横着挪不改变深度（第 32 课：深度只看视线方向）。

  • 在画布上按住右键拖。读数会显示这一次拖动（从按下开始）每个点挪了多少像素，旁边是 dx × d / D 算出来的值。
  • 没有鼠标右键，就点「合成：右键向右拖 100 px」。
  • 平移以后再用左键转一下，然后再平移：目标点变了，d 和 D 都会变，公式照样成立。

实验台的画布只有 300 px 高，所以同样拖 100 px，相机挪 100 × 42.24 ÷ 300 = 14.08（第 4 节算的 7.04 是 600 px 高的画布）。三个点各挪多少像素，和画布高度无关：dx × d / D 里没有 H。

7. 项目代码：applyPan 逐行读

项目里平移就是这个函数（mountOrbitCameraInput.ts:184–229）。dx、dy 是这次 pointermove 比上次移动了多少像素（第 37 课讲它们从哪来）。注释是课程加的；为了不超出页面宽度，课程把 panLocalMatrix 简写成 m，长行折了行：

function applyPan(camera: Camera, dx: number, dy: number): void {
  if (!(camera instanceof PerspectiveCamera) || panSpeed === 0) return
  // 当前的目标点：平移过就用平移后的，没平移过就用挂载时给的 [0, 10, 0]
  const target = targets.get(camera) ?? initialTarget
  const position = camera.transform.position
  // d：相机到目标点的距离。目标在视线正中，所以它就是目标点的深度
  const distance = Math.hypot(
    position[0] - target[0],
    position[1] - target[1],
    position[2] - target[2]
  )
  // h(d) / H × panSpeed：拖 1 像素，相机挪多少个世界单位（第 4 节）
  // clientHeight 是画布的 CSS 高度 H；横向也用它（第 32 课第 6 节）
  const unitsPerPixel =
    (2 * distance * Math.tan(camera.fovY / 2) * panSpeed) /
    Math.max(1, canvas.clientHeight)
  if (!Number.isFinite(unitsPerPixel) || unitsPerPixel === 0) return

  // 相机的局部矩阵：第 0 列（下标 0、1、2）是相机的「右」方向，
  // 第 1 列（下标 4、5、6）是「上」方向，都用世界坐标表示（第 25 课）
  camera.transform.copyLocalMatrixTo(panLocalMatrix)
  const m = panLocalMatrix // 课程为了排版起的短名字，原文每处都写 panLocalMatrix
  const rightLength = Math.hypot(m[0]!, m[1]!, m[2]!)
  const upLength = Math.hypot(m[4]!, m[5]!, m[6]!)
  // …长度为 0 或不是有限数时直接返回（:200–206）

  // 向右拖 dx：相机向左挪 dx × unitsPerPixel（负号）
  // 除以长度：把方向变成长度为 1
  const horizontal = (-dx * unitsPerPixel) / rightLength
  // 向下拖 dy（屏幕 y 向下为正）：相机向上挪，画面里的东西才会往下走
  const vertical = (dy * unitsPerPixel) / upLength
  // 新位置 = 旧位置 + horizontal × 右方向 + vertical × 上方向
  // Math.fround：按 Float32 存，和 Transform 里存的精度一致
  const nextPosition: Vec3Tuple = [
    Math.fround(position[0] + horizontal * m[0]! + vertical * m[4]!),
    Math.fround(position[1] + horizontal * m[1]! + vertical * m[5]!),
    Math.fround(position[2] + horizontal * m[2]! + vertical * m[6]!)
  ]
  // 目标点挪同样的距离：相机和目标一起平移，相机还看着目标，距离 d 也不变
  const nextTarget: Vec3Tuple = [
    target[0] + (nextPosition[0] - position[0]),
    target[1] + (nextPosition[1] - position[1]),
    target[2] + (nextPosition[2] - position[2])
  ]
  // …任何一个分量不是有限数就放弃这次平移（:221–226）
  camera.transform.setPosition(nextPosition)
  targets.set(camera, nextTarget)
}

对照第 4 节：unitsPerPixel 就是 h(d) / H，horizontal 就是 −s。相机不旋转，只改位置，所以平移后它的三根轴不变，看的方向也不变；目标点跟着挪了同样的距离，下一次旋转就绕新的目标点转。

three.js 的 OrbitControls 是同一个公式：targetDistance × tan(fov/2) 是半高，乘 2 再除以 clientHeight（本地文件 OrbitControls.js:899–910）。
