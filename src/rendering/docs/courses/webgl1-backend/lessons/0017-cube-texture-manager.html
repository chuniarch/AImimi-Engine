backend ⑤：把图片交给 GPU——CubeTextureManager 与上传作用域

HW2 的背景是一个天空盒：六张 JPEG 贴在一个大立方体的六个内壁上。CPU 上，它们是一个 CubeTexture，里面装着六张浏览器解码好的图片；要画出来，得把像素拷进 GPU 的一个 cubemap 纹理。这一课先用 HW2 的真实图片把纹理相关的 GL 调用看明白：纹理单元、上传设置、采样参数、颜色空间；再从旧引擎的写法出发一版一版补上缺的东西，最后读真实的 CubeTextureManager。

和你的目标的关系 —— HW2 每帧都要用这个 cubemap 画背景；HW1 的阴影、IBL 的环境图、你正在写的 Texture2D 上传，走的都是同一套「上传作用域」和同样的检查。这一课的 withTextureUploadState、assertTextureOperation 在 WebGL1TextureUploadSupport.ts 里，RenderTargetManager（下一课）也在用。
默认你已经会的：第 16 课第 3 节，GeometryManager 上传前「先记下、再还回」绑定，失败时删掉本次建的对象，全部成功才写进缓存；第 15 课 2.8 节或第 14 课 2.6 节讲过的「一代一个 Manager」。CubeTexture 的字段（第 12 课）1.2 节会配着 HW2 的值再列一遍。如果其中哪一条其实没懂，告诉我，我先补那一块。
这一课从零讲的：纹理的三个调用和 cubemap 的六个面；纹理单元：bindTexture 写进哪一格；四个上传设置为什么是整个 context 共用的；WebGL1 的 NPOT 限制和「纹理不完整就采样出黑色」；sRGB 纹理采样时怎样解码；上传作用域；validateStorage 每一条防的是什么；为什么 CubeTextureManager 不需要 beforeDelete；它和 Lifecycle 的关系。

1. 原始输入与需求

1.1 六张图

HW2 有四个环境预设，每个一个目录、六张 JPEG，文件名固定：posx、negx、posy、negy、posz、negz，分别贴在立方体的 +X、−X、+Y、−Y、+Z、−Z 面（顺序写死在 hw2CPUSceneConfig.ts:12–20，不按下载完成的先后）。实际尺寸（sips 实测）：

预设每面尺寸六个 JPEG 一共解码成 RGBA 后（6 × 宽 × 高 × 4 字节）
CornellBox128 × 12810.8 KB393,216 字节（384 KiB）
GraceCathedral256 × 256109.2 KB1,572,864 字节（1.5 MiB）
Skybox256 × 25625.9 KB1.5 MiB
Indoor512 × 512361.6 KB6,291,456 字节（6 MiB）

注意最后两列差了十几倍：JPEG 是压缩过的，GPU 不认 JPEG，它要的是一个一个像素。浏览器加载图片时把 JPEG 解码成像素（第 21 课的 loadHW2CubeImages 等到六张都 onload），texImage2D 拷进显存的是解码后的像素。打开 posx.jpg 的前 16 个字节： 

ff d8 ff e0 00 10 4a 46 49 46 00 01 01 00 00 01
// ff d8：JPEG 文件的开头标记；4a 46 49 46 是 ASCII 的 "JFIF"
// 后面是压缩后的数据，不是一个个像素，texImage2D 也不认它

这一课的卡片用 CornellBox 的六张图（最小，六张一共 10.8 KB，转成 data: URL 放在 assets/hw2-cornellbox-faces.js）。用 file:// 打开页面时，直接读本地 JPEG 会被浏览器当成跨源图片，texImage2D 会拒绝；data: URL 不会。

1.2 CubeTexture 里装着什么

createHW2Scene 拿到六张图以后，把它们和一份描述一起包进 CubeTexture：

// createHW2Scene.ts:320–343（节选，注释是课程加的）
const texture = retain(
  new CubeTexture({
    // 诊断用的名字，比如「GraceCathedral / Mary / …/background」
    label: settings.label + '/background',
    source: { kind: 'images', faces }, // 六个 HTMLImageElement，顺序 +X、-X、+Y、-Y、+Z、-Z
    storage: { format: 'rgba', type: 'uint8' }, // GPU 上每个像素 4 个通道、各 1 字节
    colorSpace: 'data', // 采样时不解码：shader 拿到的就是 JPEG 里的原值（2.5 节）
    sampler: {
      wrapS: 'clamp-to-edge', // 出了边就取边上的像素
      wrapT: 'clamp-to-edge',
      minFilter: 'linear', // 缩小、放大都用双线性，不用 mipmap
      magFilter: 'linear'
    },
    mipmapPolicy: 'none' // 只有原尺寸这一层
  })
)

第 12 课讲过：CubeTexture 是 CPU 上的逻辑资源，它借用这六张图（不复制像素、不关闭它们），不认识 WebGL。source.kind 还可以是 'data'：六个像素数组，每个带 width、height（比如程序生成的 HDR 环境图）。描述里的每个字段，这一课都会讲到它在 GPU 上变成了什么。

1.3 谁来要 GPU 纹理

CubeTextureManager 不主动上传。第一次画背景时，Uniforms 准备 uniform，遇到 uSkyboxMap 这个 cubeTexture 参数，才去要它的 GPU 表示： 

// WebGL1Uniforms.ts:164–173（prepare 里处理 cubeTexture 参数的一段，注释是课程加的）
if (parameter.type === 'cubeTexture') {
  const unit = nextTextureUnit++ // 背景只有一个 samplerCube：用单元 0
  // resolveCube 就是 resources.cubeTextures.get（WebGL1Backend.ts:295）：
  // 第一次会上传六面，以后直接交回缓存
  const resource = this.resolveCube(parameter.value)

  // prepare 只准备、不执行：交回一个函数，draw 时由 upload 依次调用
  return () => {
    this.gl.activeTexture(this.gl.TEXTURE0 + unit) // 选中单元 0
    // 放进单元 0 的 cube 格子
    this.gl.bindTexture(this.gl.TEXTURE_CUBE_MAP, resource.handle)
    this.gl.uniform1i(entry.location, unit) // 告诉 shader：uSkyboxMap 读单元 0
  }
}

1.4 需求：要应付哪些情况

  1. 同一个 CubeTexture 只上传一次。Indoor 一次 6 MiB，不能每帧拷一遍。
  2. 上传不受别人留下的设置影响，也不把自己的设置留给别人。上传设置和纹理绑定都是整个 context 共用的（2.2、2.3 节），旧引擎的代码和新后端在同一个 canvas 上共用一个 context。
  3. 六面要么全传上去，要么一个都不留。传到第五面显存不够，前面建的纹理要删掉，缓存里也不能出现它。
  4. WebGL1 做不到的组合，在碰 GPU 之前就拒绝。NPOT 配 mipmap、float 没有扩展、要 sRGB 却没有 EXT_sRGB……这些做下去不一定报错，只是采样出黑色或颜色不对（2.4、2.5 节实测）。
  5. 颜色空间说到做到。描述里写 sRGB，采样时就要解码成线性值；写 data，就原样交给 shader。
  6. 释放、关闭、context 丢失时的规矩和前两课的 Manager 一样：释放时删干净，丢失时不乱发命令，恢复后能重新上传。

2. 先把 GL 调用看明白

2.1 纹理的三步，和 cubemap 的六个面

和 buffer 一样（第 16 课 2.1 节），纹理也是「先建、再绑、再往里写」：

const t = gl.createTexture()             // ① 建一个空的纹理对象，拿到句柄
gl.bindTexture(gl.TEXTURE_CUBE_MAP, t)   // ② 绑到 cube 格子上（2.2 节说是哪一格）
// ③ 往「当前绑着的那个纹理」的某一面写像素。cubemap 有六面，各有一个 target：
//    TEXTURE_CUBE_MAP_POSITIVE_X = 0x8515，NEGATIVE_X = 0x8516，POSITIVE_Y = 0x8517，
//    NEGATIVE_Y = 0x8518，POSITIVE_Z = 0x8519，NEGATIVE_Z = 0x851A，正好连续，
//    所以代码里写 TEXTURE_CUBE_MAP_POSITIVE_X + i

// 来源是图片：图片自带宽高，6 个参数
gl.texImage2D(gl.TEXTURE_CUBE_MAP_POSITIVE_X, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, image)
//            哪一面                          第 0 层  GPU 上的格式  来源格式  每通道 1 字节

// 来源是像素数组：数组不知道自己多宽多高，9 个参数
gl.texImage2D(gl.TEXTURE_CUBE_MAP_POSITIVE_X, 0, gl.RGBA, 256, 256, 0, gl.RGBA,
              gl.UNSIGNED_BYTE, pixels)  // pixels：256 × 256 × 4 = 262,144 字节
//                                              宽   高  边框（WebGL 里必须是 0）

2.2 纹理单元：bindTexture 写进哪一格

shader 里的 samplerCube uSkyboxMap 并不直接存一个纹理，它存的是一个单元号。纹理单元 (texture unit) 是一排格子：每个单元有一个 2D 格子和一个 cube 格子。context 里还有一个「当前单元」(ACTIVE_TEXTURE)，bindTexture 写进的是当前单元的那个格子： 

// 整个 context 一份（SwiftShader 实测 32 个单元；WebGL1 至少保证 8 个）
// ACTIVE_TEXTURE → 单元 0
// 单元    TEXTURE_2D 格子    TEXTURE_CUBE_MAP 格子
//   0          null               null
//   1          null               null
//   …
//  31          null               null

gl.activeTexture(gl.TEXTURE3)              // 当前单元换成 3
gl.bindTexture(gl.TEXTURE_CUBE_MAP, A)     // 单元 3 的 cube 格子 = A
gl.activeTexture(gl.TEXTURE0)              // 当前单元换回 0
gl.bindTexture(gl.TEXTURE_CUBE_MAP, B)     // 单元 0 的 cube 格子 = B；单元 3 还是 A
gl.uniform1i(uSkyboxMapLocation, 3)        // shader 采样 uSkyboxMap 时读单元 3 → A

这和第 16 课的 ARRAY_BUFFER 是一类东西：整个 context 共用、藏在「当前」后面的状态。谁调用 bindTexture，就换掉了当前单元那一格里原来放的纹理。上传纹理必须先 bindTexture（第 ② 步），所以上传本身就会动到别人的格子——这就是需求 2 的一半。

2.3 上传设置：整个 context 只有一份

texImage2D 怎样把来源的字节排进纹理，还受四个上传设置控制，用 pixelStorei 设置。它们不存在纹理里，而是整个 context 一份：谁最后设，之后所有的 texImage2D 都照它来。四个设置、它们的初始值（实测，和规范一致）和作用：

设置初始值管什么实测
UNPACK_ALIGNMENT4数组来源每一行的起点按几字节对齐3 × 3 的 RGB 面，每行 9 字节，按 4 对齐要补到 12，一共要 12 + 12 + 9 = 33 字节；只给 27 字节 → INVALID_OPERATION（1282）。设成 1 → 0
UNPACK_FLIP_Y_WEBGLfalse要不要上下翻转（最后一行最先传）上红下蓝的 2 × 2 图：false 时第 0 行是红，true 时第 0 行是蓝；对像素数组也生效；对 ImageBitmap 不起作用
UNPACK_PREMULTIPLY_ALPHA_WEBGLfalse要不要把 alpha 乘进颜色半透明像素 (200, 100, 50, 0.5)：false 时存成 (199, 100, 50, 128)，true 时存成 (100, 50, 25, 128)
UNPACK_COLORSPACE_CONVERSION_WEBGLBROWSER_DEFAULT_WEBGL要不要让浏览器按图片自带的色彩配置转换颜色NONE 时除了转成 RGBA，不做任何颜色转换（规范原话）；默认值下，带色彩配置的图片（比如 Display P3 拍的照片）可能被改值

因为是全局的，一处设了忘了还，就会影响后面所有人。旧引擎就有一处现成的例子：它给 2D 纹理上传前把 FLIP_Y 设成 true，传完再手动设回 false： 

// 旧引擎 src/textures/Texture.ts:66–72（原注释保留，挪到了行上方）
gl.bindTexture(gl.TEXTURE_2D, this.handle)
// 设置为 true 后，所有后续的 texImage2D 调用都会翻转 Y 轴，直到手动设回 false
gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)
gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, image)

this.setupFiltering(image.width, image.height)

gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, false) // 恢复！
// 课程注：texImage2D 或 setupFiltering 一旦抛错，上面这一行就走不到，
// FLIP_Y 会一直是 true，之后谁上传都被翻转

这就是需求 2 的另一半：上传之前，不能假设这四个设置是初始值；上传之后，也不能把自己设的值留给别人。

2.4 采样参数，和 WebGL1 的 NPOT 限制

texParameteri 设的是采样参数：出了边界怎么办（wrap）、缩小放大时怎么取（filter）。和上传设置不同，它们存在纹理对象里，绑到哪个单元都跟着走。

WebGL1 对边长不是 2 的幂的纹理（NPOT，比如 100、300）有限制：wrap 只能是 CLAMP_TO_EDGE，缩小过滤只能是 NEAREST 或 LINEAR（不能用 mipmap），也不能 generateMipmap。违反了会怎样？下表是在无界面 Chrome 里实测的：用一个纯色 (200, 100, 50) 的 cubemap，画一个像素去采样它。

边长wrap缩小过滤采样结果getError
4（2 的幂）CLAMPLINEAR(200, 100, 50, 255)0
3（NPOT）CLAMPLINEAR(200, 100, 50, 255)0
3（NPOT）REPEATLINEAR(0, 0, 0, 255)0
3（NPOT）CLAMPLINEAR_MIPMAP_LINEAR(0, 0, 0, 255)0
4（2 的幂）CLAMPLINEAR_MIPMAP_LINEAR，但没生成 mipmap(0, 0, 0, 255)0

规则违反时，纹理叫作「不完整」(incomplete)：采样一律得到黑色 (0, 0, 0, 1)，没有任何错误码。另外，对 NPOT 纹理调用 generateMipmap 会报 INVALID_OPERATION（1282，实测）。最后一行说明，就算是 2 的幂，用了 mipmap 过滤却没有 mipmap，也一样是黑的。这条和 WebGL1 无关，所以 CPU 的 Texture 在构造时就拒绝它（Texture.ts:208–210）；NPOT 那几条只是 WebGL1 的限制，留给后端的 CubeTextureManager 检查（3.4 节）。这和第 10 课的 Geometry 一样分工：和后端无关的规则由 CPU 资源查，和设备能力有关的由后端查。

2.5 颜色空间：sRGB 纹理在采样时解码

先把数学说清楚。JPEG 里存的 8 位颜色值 v（0～255 的整数）是「为显示器编码过的」(sRGB 编码)，不是光的强度。记 s = v / 255（0～1）。光照计算要用线性值 c（和光的强度成正比），sRGB 的解码公式是： 

c = s / 12.92                        当 s ≤ 0.04045
c = ((s + 0.055) / 1.055) ^ 2.4      当 s > 0.04045

例：v = 128 → s = 128 / 255 = 0.50196
    c = ((0.50196 + 0.055) / 1.055) ^ 2.4 = 0.52793 ^ 2.4 = 0.21586
    写回 8 位：0.21586 × 255 = 55.04 → 55

EXT_sRGB 扩展提供 SRGB_ALPHA_EXT 格式：像素照样按原值存，GPU 在采样时自动做上面的解码。实测：同样存 128，普通 RGBA 采样得到 128（也就是 0.502），SRGB_ALPHA_EXT 采样得到 55（0.216）。所以描述里写 colorSpace: 'srgb' 时，Manager 用 SRGB_ALPHA_EXT 上传，shader 拿到的已经是线性值，不能再自己解码一次。

HW2 现在写的是 'data'：原值交给 shader，背景 shader 直接把它写到屏幕上。JPEG 的值本来就是为显示编码的，所以看起来是对的。如果只把标签改成 'srgb'，shader 拿到的是 0.216 而不是 0.502，又没有在输出时编码回去，背景会变暗。这就是 createHW2Scene 那条 TODO 说的：colorSpace、背景 shader、输出变换要一起改（createHW2Scene.ts:325–334）。

3. 一版一版写

3.1 第 1 版：旧引擎的写法

旧引擎的 CubeMapTexture 就是教程写法：建、绑、传六面、设采样参数，最后解绑。

// 第 1 版：旧引擎的写法。GL 调用和 src/textures/CubeMapTexture.ts:64–108 一样，
// 改写成了函数，去掉了注释掉的代码和错误类
function uploadCubeV1(
  gl: WebGLRenderingContext,
  faces: readonly TexImageSource[] // 六张图，顺序 +X、-X、+Y、-Y、+Z、-Z
): WebGLTexture {
  const handle = gl.createTexture()!
  // 绑在「当前单元」的 cube 格子上：那一格原来放着谁，现在被换掉了
  gl.bindTexture(gl.TEXTURE_CUBE_MAP, handle)

  for (let i = 0; i < faces.length; i++) {
    // +X、-X、+Y、-Y、+Z、-Z 是连续的六个数：0x8515 + i。
    // 用的是此刻 context 里的上传设置：别人留下的 FLIP_Y、ALIGNMENT 照样生效。
    // 不查 getError：这一面没传上去，函数也照样往下走
    const face = gl.TEXTURE_CUBE_MAP_POSITIVE_X + i
    gl.texImage2D(face, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, faces[i]!)
  }

  // 采样参数存在这个纹理对象里（和上传设置不同，不是整个 context 共用的）
  gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_MIN_FILTER, gl.LINEAR)
  gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_MAG_FILTER, gl.LINEAR)
  gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE)
  gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE)

  // 「收尾」：把当前单元的 cube 格子清空。原来放在那里的纹理也就没了
  gl.bindTexture(gl.TEXTURE_CUBE_MAP, null)
  return handle
}

对照 1.4 节的需求，它有三个问题：

  1. 继承别人的上传设置。它不碰 pixelStorei，用的是此刻 context 里的值。假如旧引擎的 Texture.ts 在 2.3 节那两行之间抛了错，FLIP_Y 留成 true，这六面就全被上下翻转了。
  2. 动了当前单元的格子，最后清成 null。假如当前单元是 2，单元 2 的 cube 格子里原来放着别人的纹理 X，第一行 bindTexture 换掉了它，最后一行又清成 null。X 不会自己回来。
  3. 不查错误，一面失败也照样交出纹理。显存不够时 texImage2D 不抛异常，只留一个错误码。第 1 版不问 getError，于是交出一个缺了一面的 cubemap：缺面的 cubemap 是「不完整」的，采样整个都是黑色。

另外，它也没有缓存和释放的规矩，那是旧引擎里 Texture 对象自己管的。下面两张卡片只跑第 1 版：

3.2 第 2 版：上传作用域，加上「六面都成功才交出去」

// 第 2 版：上传作用域（先记下、设成自己要的、再还回），加上「六面都成功才交出去」
function uploadCubeV2(
  gl: WebGLRenderingContext,
  faces: readonly TexImageSource[] // 六张图，顺序 +X、-X、+Y、-Y、+Z、-Z
): WebGLTexture {
  // ① 先记下别人的：当前是第几个单元、这个单元 cube 格子里的纹理、四个上传设置
  const activeUnit = gl.getParameter(gl.ACTIVE_TEXTURE) as number
  const previous = gl.getParameter(gl.TEXTURE_BINDING_CUBE_MAP) as WebGLTexture | null
  const alignment = gl.getParameter(gl.UNPACK_ALIGNMENT) as number
  const flip = gl.getParameter(gl.UNPACK_FLIP_Y_WEBGL) as boolean
  const premultiply = gl.getParameter(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL) as boolean
  const conversion = gl.getParameter(gl.UNPACK_COLORSPACE_CONVERSION_WEBGL) as number

  let handle: WebGLTexture | null = null
  try {
    // ② 设成自己要的，不管别人留下的是什么
    gl.pixelStorei(gl.UNPACK_ALIGNMENT, 1) // 每行紧挨着，不补齐到 4 字节
    gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, false) // cubemap 的面不翻转
    gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, false) // 颜色原样，不乘 alpha
    gl.pixelStorei(gl.UNPACK_COLORSPACE_CONVERSION_WEBGL, gl.NONE) // 浏览器不做颜色转换

    handle = gl.createTexture()!
    gl.bindTexture(gl.TEXTURE_CUBE_MAP, handle)
    for (let i = 0; i < 6; i++) {
      const face = gl.TEXTURE_CUBE_MAP_POSITIVE_X + i
      gl.texImage2D(face, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, faces[i]!)
      const error = gl.getError() // 每传一面问一次：显存不够时 GL 只记一个错误码
      if (error !== gl.NO_ERROR) throw new Error('face ' + i + ': GL error ' + error)
    }
    gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_MIN_FILTER, gl.LINEAR)
    gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_MAG_FILTER, gl.LINEAR)
    gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE)
    gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE)
    return handle // ③ 六面都成功，才把纹理交出去
  } catch (error) {
    if (handle !== null) gl.deleteTexture(handle) // 半成品删掉，不交给任何人
    throw error
  } finally {
    // ④ 不管成功失败，把第 ① 步记下的东西原样还回去
    gl.activeTexture(activeUnit)
    gl.bindTexture(gl.TEXTURE_CUBE_MAP, previous)
    gl.pixelStorei(gl.UNPACK_ALIGNMENT, alignment)
    gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, flip)
    gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, premultiply)
    gl.pixelStorei(gl.UNPACK_COLORSPACE_CONVERSION_WEBGL, conversion)
  }
}

思路和第 16 课 GeometryManager 的第 2 版一样：先记下、设成自己要的、用完还回去。四个上传设置设成固定值，于是不管别人留下什么，这次上传的结果都一样；finally 保证不管成功还是抛错，都把别人的东西还回去。再加上每面问一次 getError、失败就删掉半成品。这个「记下 → 设定 → 还回」的范围，代码里叫上传作用域。同样两个场景，换成第 2 版：

第 2 版还缺：缓存（需求 1）；WebGL1 做不到的组合要先拒绝（需求 4）；sRGB 和 float（需求 5）；进门先清掉别人留下的错误（不然别人的错误会算成「第 0 面上传失败」，第 15 课 preflight 讲过）；context 丢失的处理（需求 6）。这些在真实代码里。

3.3 真实代码：get

get 分前后两半。前半全是 CPU 上的检查，一个 GPU 对象都还没建：

// WebGL1CubeTextureManager.ts:80–113（get 的前半：还没碰 GPU；注释是课程加的）
get(texture: CubeTexture): WebGL1CubeTextureResource {
  this.assertReady() // Manager 关了吗？context 丢了吗（第 4 节）？
  if (texture.disposed) throw new ResourceDisposedError('CubeTexture')
  const cached = this.entries.get(texture)
  if (cached !== undefined) return cached.resource // 第二次起：一条 GL 命令都不发

  const gl = this.gl
  let handle: WebGLTexture | null = null // 账本：建出来的纹理，失败时靠它删

  try {
    // 进门先取一次 getError：别人留下的错误不能算到这次头上（第 15 课 preflight）
    assertTextureOperation(gl, 'begin cube upload', texture.label)
    // { kind: 'images', faces: 六张图 }，或 { kind: 'data', faces: 六个像素数组 }
    const source = texture.copySource()

    // 每一面的真实像素尺寸：图片读 naturalWidth（不是 CSS 宽度），数据直接带着 width/height
    const dimensionAt = (index: 0 | 1 | 2 | 3 | 4 | 5) =>
      source.kind === 'images'
        ? imageDimensions(source.faces[index], texture.label)
        : source.faces[index]

    const faces: CubeFaces<{ readonly width: number; readonly height: number }> = [
      dimensionAt(0), dimensionAt(1), dimensionAt(2),
      dimensionAt(3), dimensionAt(4), dimensionAt(5)
    ]

    // 和后端无关的规则：每面正方形、六面一样大（GraceCathedral：六个 256 × 256）
    assertValidCubeFaceDimensions(
      faces,
      (reason) => new InvalidTextureSourceError(texture.label, reason)
    )

    const size = faces[0].width // 256
    // 和 WebGL1 有关的规则：尺寸上限、NPOT、通道、float、sRGB（3.4 节）。
    // 交回 texImage2D 要用的格式：RGBA，或 sRGB 时的 SRGB_ALPHA_EXT
    const format = this.validateStorage(texture, source.kind, size)
    const type = texture.storage.type === 'float32' ? gl.FLOAT : gl.UNSIGNED_BYTE

两个细节。imageDimensions 读的是 naturalWidth、naturalHeight，也就是图片真实的像素尺寸；width 属性可能被 CSS 或 HTML 改过，不能用。它还检查 image.complete：图片没加载完就 texImage2D，会传上去一张 0 × 0 的空图（:40–53）。另一个是检查的分工：「正方形、六面一样大」对任何后端都成立，交给 CPU 侧的 assertValidCubeFaceDimensions；「NPOT 不能 mipmap」只是 WebGL1 的限制，交给 validateStorage。

后半在上传作用域里建纹理、传六面、设采样参数，全部成功才发布：

// WebGL1CubeTextureManager.ts:115–189（get 的后半，接上一段；注释是课程加的）
    // 上传作用域：进去前记下别人的状态、设成固定值，出来时还回去（3.5 节）
    withTextureUploadState(gl, gl.TEXTURE_CUBE_MAP, () => {
      handle = requireNonNull(
        gl.createTexture(), // context 丢了会返回 null
        () => new WebGLResourceCreationError('cube-texture', texture.label)
      )
      gl.bindTexture(gl.TEXTURE_CUBE_MAP, handle)

      for (let index = 0; index < 6; index++) {
        const faceTarget = gl.TEXTURE_CUBE_MAP_POSITIVE_X + index // 0x8515 + index
        if (source.kind === 'data') {
          // 数组没有尺寸，要显式给 width、height（9 个参数的那个重载）
          const face = source.faces[index]!
          gl.texImage2D(faceTarget, 0, format, size, size, 0, format, type, face.data)
        } else {
          // 图片自带尺寸（6 个参数的那个重载）
          gl.texImage2D(faceTarget, 0, format, format, type, source.faces[index]!)
        }
        // 每面问一次：显存不够时 texImage2D 不抛异常，只留错误码
        assertTextureOperation(gl, 'upload cube face ' + index, texture.label)
      }

      // CPU 描述里的字符串 → GL 常量。Record 要求每个取值都写到，漏一个编译不过
      const wraps: Record<TextureWrapMode, number> = {
        'clamp-to-edge': gl.CLAMP_TO_EDGE,
        repeat: gl.REPEAT,
        'mirrored-repeat': gl.MIRRORED_REPEAT
      }
      const filters: Record<TextureMinFilter, number> = {
        nearest: gl.NEAREST,
        linear: gl.LINEAR,
        'nearest-mipmap-nearest': gl.NEAREST_MIPMAP_NEAREST,
        'linear-mipmap-nearest': gl.LINEAR_MIPMAP_NEAREST,
        'nearest-mipmap-linear': gl.NEAREST_MIPMAP_LINEAR,
        'linear-mipmap-linear': gl.LINEAR_MIPMAP_LINEAR
      }

      // 采样参数：存进这个纹理对象（HW2：clamp-to-edge、linear）
      gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_WRAP_S, wraps[texture.sampler.wrapS])
      gl.texParameteri(gl.TEXTURE_CUBE_MAP, gl.TEXTURE_WRAP_T, wraps[texture.sampler.wrapT])
      gl.texParameteri(
        gl.TEXTURE_CUBE_MAP,
        gl.TEXTURE_MIN_FILTER,
        filters[texture.sampler.minFilter]
      )
      gl.texParameteri(
        gl.TEXTURE_CUBE_MAP,
        gl.TEXTURE_MAG_FILTER,
        filters[texture.sampler.magFilter]
      )

      if (texture.mipmapPolicy === 'generate') gl.generateMipmap(gl.TEXTURE_CUBE_MAP)
      assertTextureOperation(gl, 'configure cubemap', texture.label)
    })

    // 作用域里的还原也是 GL 命令，出来再问一次
    assertTextureOperation(gl, 'restore cube upload state', texture.label)
    // 防御：理论上同步过程中没人能释放它；万一有，也不把它写进缓存
    if (texture.disposed) throw new ResourceDisposedError('CubeTexture')

    const resource = Object.freeze({
      handle: requireNonNull<WebGLTexture>(
        handle,
        () => new WebGLResourceCreationError('cube-texture', texture.label)
      ),
      target: gl.TEXTURE_CUBE_MAP
    })

    // 唯一的发布点：订阅释放、写进缓存，然后交出去
    const unsubscribe = texture.onDispose(() => this.release(texture))
    this.entries.set(texture, { resource, unsubscribe })
    return resource
  } catch (error: unknown) {
    if (this.lost || gl.isContextLost()) {
      this.invalidateForContextLoss() // 丢了：不 delete，整个 Manager 作废（第 4 节）
      throw new WebGLContextLostError('create cubemap')
    }
    if (handle !== null) gl.deleteTexture(handle) // 半成品删掉
    throw error
  } finally {
    this.hooks.invalidateState() // 告诉 State：有人绕过它动过 GL（第 6 节有一道想一想）
  }
}

3.4 validateStorage：每一条防的是什么

// WebGL1CubeTextureManager.ts:203–262（注释是课程加的）
private validateStorage(
  texture: CubeTexture,
  sourceKind: 'images' | 'data',
  size: number
): number {
  const gl = this.gl
  const unsupported = (reason: string): never => {
    throw new UnsupportedRenderFeatureError('cubemap ' + texture.label, reason)
  }

  // ① 尺寸上限：设备说了算（SwiftShader 是 16384；WebGL1 只保证 16）
  if (
    size > requireTextureLimit(gl, gl.MAX_CUBE_MAP_TEXTURE_SIZE, 'MAX_CUBE_MAP_TEXTURE_SIZE')
  ) {
    unsupported('face size exceeds device limit')
  }

  // ② NPOT：边长不是 2 的幂（比如 100、300）时，只能 clamp、不能用 mipmap。
  //    否则纹理「不完整」，采样得到黑色，而且不报错（2.4 节实测）
  const pot = Number.isInteger(Math.log2(size)) // 256 → log2 = 8，是整数
  if (
    !pot &&
    (texture.sampler.wrapS !== 'clamp-to-edge' ||
      texture.sampler.wrapT !== 'clamp-to-edge' ||
      texture.mipmapPolicy !== 'none' ||
      (texture.sampler.minFilter !== 'nearest' && texture.sampler.minFilter !== 'linear'))
  )
    unsupported('WebGL1 NPOT requires clamp-to-edge, base-level filtering and no mipmaps')

  // ③ 通道：只做 rgb、rgba。WebGL1 没有 R、RG 格式，最接近的 LUMINANCE 采样时
  //    会把一个通道抄到 r、g、b 三个，和 'r' 的意思不同，所以不冒充
  const storage = texture.storage
  if (storage.format !== 'rgb' && storage.format !== 'rgba') {
    unsupported('r/rg channel mapping is not implemented')
  }

  // ④ float32（HDR 环境图）：要扩展，而且限制多
  if (storage.type === 'float32') {
    // 图片解码出来都是 8 位，float 只能来自像素数组
    if (sourceKind !== 'data') unsupported('float32 requires CPU pixel data')
    if (this.capabilities.textureFloat === null)
      unsupported('OES_texture_float is required')

    const linear =
      texture.sampler.magFilter === 'linear' || texture.sampler.minFilter.includes('linear')

    // 能存 float 不等于能对 float 做线性过滤：那是另一个扩展
    if (linear && this.capabilities.textureFloatLinear === null) {
      unsupported('OES_texture_float_linear is required')
    }
    if (texture.mipmapPolicy !== 'none')
      unsupported('float32 mipmap generation is not implemented')
    if (texture.colorSpace === 'srgb') unsupported('sRGB storage requires uint8')
  }

  // ⑤ sRGB：要 EXT_sRGB，采样时由 GPU 解码成线性值（2.5 节）。
  //    第一次用到才查扩展，查过就记住：undefined = 还没查，null = 查过、没有
  if (texture.colorSpace === 'srgb') {
    if (this.srgbExtension === undefined) this.srgbExtension = gl.getExtension('EXT_sRGB')
    if (gl.isContextLost()) throw new WebGLContextLostError('query EXT_sRGB')

    const extension = this.srgbExtension
    if (extension === null) {
      // 没有就报错，不悄悄当成 RGBA 存：那样颜色会偏亮，而且没人知道
      throw new UnsupportedRenderFeatureError(
        'sRGB cubemap',
        'EXT_sRGB is required; no implicit color-space fallback'
      )
    }
    return storage.format === 'rgb' ? extension.SRGB_EXT : extension.SRGB_ALPHA_EXT
  }

  // HW2 走到这里：rgba + data → gl.RGBA
  return storage.format === 'rgb' ? gl.RGB : gl.RGBA
}

这五条有一个共同点：做下去不一定报错，只是结果悄悄不对。NPOT 配 REPEAT 采样出黑色（2.4 节）；拿 LUMINANCE 冒充 'r' 会让 g、b 也有值；没有 EXT_sRGB 就当 RGBA 存，颜色偏亮、没人发现。所以要在碰 GPU 之前，按描述逐条核对，做不到就明确报 UnsupportedRenderFeatureError。还要注意 srgbExtension 的三个值：undefined 是「还没查」，null 是「查过、没有」，和第 14 课 State 里 undefined 与 null 的区别是同一个思路。

3.4 补：format、type、colorSpace、mipmap 之间的约束从哪来（2026-10-12 补）

上面的五条是按代码顺序读的。换一个角度：描述里的四项各管一件事，约束不是随便两两定的，而是有两个源头。一是一个纹素从显存到 shader 要经过四步，后一步对前一步交出来的东西有要求；二是 WebGL1 只给某些组合配了硬件或扩展。先看这四步： 

 ① 存：每个像素几个数 × 每个数怎么存          ← format × type
        rgba × uint8 = 4 字节；rgba × float32 = 16 字节
 ② 选：从哪一层 mipmap 取、几个纹素怎么混合    ← mipmapPolicy + minFilter / magFilter
 ③ 解：把存的数换回「真实的量」               ← colorSpace
        srgb：GPU 采样时解码（128 → 55）；linear、data：原样
 ④ 交给 shader 一个 vec4
项回答的问题例子（无界面 Chrome 实测）
format每个像素几个数rgba 4 个，rgb 3 个，r 1 个
type每个数怎么存uint8 存 0～255 的整数，shader 读到 k / 255：0.3 存成 77，读回 0.30196；3.7 存不下，最大 1.0。float32 存 4 字节浮点：3.7 原样（采样后乘 0.25 读到 236，约 0.925 × 255）
colorSpace存进去之前用了什么编码规则srgb 存的是编码值，采样时 GPU 解码；linear 存的就是线性颜色；data 不是颜色（法线、LUT、打包的深度），任何时候都不转换
mipmapPolicy有没有预先缩小的副本generate：上传后 generateMipmap，每 2 × 2 求平均得到 1/2、1/4……各层；minFilter 决定采样时用不用

逐条看约束。「谁规定」一栏分清哪些是 GL 的硬性规定、哪些是项目自己的选择：

组合规则为什么（实测）谁规定在哪查
mipmap 过滤 × mipmapPolicy带 mipmap 的过滤要配 generate要读第 1、2…… 层，没有就「不完整」，采样黑色（2.4 节）GL，所有后端CPU：Texture.ts:208

type × 数组Uint8Array ↔ uint8，Float32Array ↔ float32；长度 = 宽 × 高 × 通道数第 12 课 4.2 节项目CPU：texturePixelSnapshot.ts:108–126

表里「Manager ②③④」指 3.4 节节选里的编号。另外两条不算约束但要记得：SRGB_ALPHA 只解码 RGB、不动 alpha（存 128 采样得 (55, 55, 55, 128)）；linear 和 data 在 WebGL1 里处理完全一样，区别只在语义上，将来做色调映射、颜色管理时 data 绝不能被转换。

少查了一条：srgb × generate。EXT_sRGB 的 OpenGL ES 原文（第 3.7.11 节 Mipmap Generation）：「If the format of a texture is sRGB, the error INVALID_OPERATION is generated.」理由在它的 Issue 4：正确的 mipmap 要先解码成线性值、再平均、再编码回去；直接平均编码值会偏暗，比如黑 0 和白 255 平均是 127.5，解码后是 0.214，而正确的平均是线性 0.5，应该存 188。当年硬件不都支持正确的做法，ES 2.0 的扩展干脆禁止。

validateStorage 的五条里没有这一条，所以 colorSpace: 'srgb' 加 mipmapPolicy: 'generate' 能通过检查：纹理照常建好、六面传完，到 generateMipmap 才留下 0x502，被 assertTextureOperation 拦下，抛出笼统的 WebGLOperationError（configure cubemap），catch 把纹理删掉。结果是安全的，只是报得晚、看不出原因。Texture2DManager 的 validateStorage 一样（第 29 课）。这条应该放在 WebGL1 的 Manager 里，在 createTexture 之前用 UnsupportedRenderFeatureError 说清楚；不放进 CPU 的 Texture，因为 OpenGL ES 3.0 / WebGL2 的 generateMipmap 只要求格式可渲染、可过滤，SRGB8_ALPHA8 两条都满足。

以后自己怎样推出这类约束：拿任意两项问两个问题。一，后一步要的东西，前一步一定给得出吗？（mipmap 过滤要读第 1 层，可 mipmapPolicy 可能没生成；generateMipmap 要求平均，可 float 不一定能过滤，sRGB 不能直接平均。）二，这台设备给这个组合配了硬件吗？去扩展规范的格式表里找，或者搜「generates INVALID_OPERATION」这类句子，上面这条就是这样查出来的。查出来以后，用第 29 课 8.1 节的三个问题决定放在哪一层、哪个时刻查。

3.5 上传作用域：withTextureUploadState

// WebGL1TextureUploadSupport.ts:62–94（注释是课程加的）
export function withTextureUploadState<T>(
  gl: WebGLRenderingContext,
  target: number, // TEXTURE_CUBE_MAP 或 TEXTURE_2D：只记下、还原这一种格子
  callback: () => T
): T {
  // ① 记下别人的。注意不切到 TEXTURE0：就在当前单元上做，少动一样东西
  const activeUnit = gl.getParameter(gl.ACTIVE_TEXTURE) as number
  const bindingParameter =
    target === gl.TEXTURE_CUBE_MAP ? gl.TEXTURE_BINDING_CUBE_MAP : gl.TEXTURE_BINDING_2D
  const texture = gl.getParameter(bindingParameter) as WebGLTexture | null
  const alignment = gl.getParameter(gl.UNPACK_ALIGNMENT) as number
  const flip = gl.getParameter(gl.UNPACK_FLIP_Y_WEBGL) as boolean
  const premultiply = gl.getParameter(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL) as boolean
  const conversion = gl.getParameter(gl.UNPACK_COLORSPACE_CONVERSION_WEBGL) as number

  // 丢失时 getParameter 只会返回 null 之类的默认值，记下来也没用
  if (gl.isContextLost()) throw new WebGLContextLostError('capture texture upload state')

  try {
    // ② 设成固定值：不管别人留下什么，这次上传的结果都一样
    gl.pixelStorei(gl.UNPACK_ALIGNMENT, 1)
    gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, false)
    gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, false)
    gl.pixelStorei(gl.UNPACK_COLORSPACE_CONVERSION_WEBGL, gl.NONE)
    return callback() // 真正的上传：createTexture、bindTexture、texImage2D……
  } finally {
    // ③ 不管 callback 成功还是抛错，都还回去；丢了就不发命令（旧状态已经没意义）
    if (!gl.isContextLost()) {
      gl.activeTexture(activeUnit)
      gl.bindTexture(target, texture)
      gl.pixelStorei(gl.UNPACK_ALIGNMENT, alignment)
      gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, flip)
      gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, premultiply)
      gl.pixelStorei(gl.UNPACK_COLORSPACE_CONVERSION_WEBGL, conversion)
    }
  }
}

四个固定值各有理由：

  • ALIGNMENT = 1：CPU 上的像素数组是一行紧挨一行的，宽度为 3 的 RGB 数据每行 9 字节，按默认的 4 对齐会多要字节（2.3 节）。
  • FLIP_Y = false：cubemap 的六个面本来就按「图片的左上角是第一个像素」排，不需要翻转（three.js 的 CubeTexture 也把 flipY 默认设成 false）；像素数组的第 0 行就是第 0 行。
  • PREMULTIPLY = false：颜色原样存，要不要预乘由使用它的 shader 决定。
  • CONVERSION = NONE：不让浏览器按图片自带的色彩配置改值。颜色怎么解释由描述里的 colorSpace 决定（2.5 节），不由浏览器猜。

还有两点。第一，它不切换到 TEXTURE0，就在当前单元上做，只动「当前单元的这一种格子」，再还回去，能少动一样就少动一样。第二，ImageBitmap 不看这三个 WebGL 设置（规范如此，2.3 节实测 FLIP_Y 对它不起作用），它的方向和预乘要在 createImageBitmap 时就定好，所以注释里说「不能靠 pixelStore 补救」。RenderTargetManager 建颜色附件时也用这个作用域（下一课）。

3.6 释放：为什么没有 beforeDelete

// WebGL1CubeTextureManager.ts:265–304（注释是课程加的）

// CubeTexture.dispose() → 订阅的回调 → release
release(texture: CubeTexture): void {
  if (this.lost || this.gl.isContextLost()) {
    this.invalidateForContextLoss() // 丢了：不发 delete
    return
  }

  const entry = this.entries.get(texture)
  if (entry === undefined) return // 从没上传过，或已经删过

  this.entries.delete(texture) // 先从缓存拿掉
  entry.unsubscribe()
  this.gl.deleteTexture(entry.resource.handle) // 再删 GPU 纹理，没有 beforeDelete（3.6 节）
  this.hooks.invalidateState()
}

// context 丢了：只丢记录和订阅，不 delete（第 4 节）
invalidateForContextLoss(): void {
  this.lost = true // 这个 Manager 永远不再用
  for (const entry of this.entries.values()) entry.unsubscribe()
  this.entries.clear()
  this.hooks.invalidateState()
}

// Backend 关闭：先退订全部，再删全部；CPU 的 CubeTexture 不动
dispose(): void {
  if (this.disposed) return
  this.disposed = true

  const entries = [...this.entries.values()]
  this.entries.clear()
  for (const entry of entries) entry.unsubscribe()

  if (this.lost || this.gl.isContextLost()) {
    this.invalidateForContextLoss()
    return
  }

  for (const entry of entries) this.gl.deleteTexture(entry.resource.handle)
  this.hooks.invalidateState()
}

和前两课比，这里少了 beforeDelete。GeometryManager 和 ProgramManager 需要它，是因为顶点输入按 buffer 和 program 录了 VAO（第 16 课 4.4 节）：删 buffer 或 program 之前，得先让录了它们的 VAO 放手。纹理没有这样的「下游」：Uniforms 每次 draw 都重新 bindTexture，不缓存任何按纹理建的 GPU 对象。所以 release 直接删就行。

4. 和 Lifecycle 的关系

第 13 课第 2 节说，context 丢了以后，Backend 要把旧的一代作废、再建新的一代。CubeTextureManager 在这两件事里做的事：

  • 一代一个 CubeTextureManager。createGeneration 新建 ResourceManager（WebGL1Backend.ts:259–302），它再新建 CubeTextureManager（WebGL1ResourceManager.ts:108）。Uniforms 拿到的 resolveCube 也是这一代的（Backend.ts:295）。缓存跟着 Manager 走，所以也是一代一份。
  • lost 事件到达：丢记录、退订，不 delete。ResourceManager 逐个通知 Manager（WebGL1ResourceManager.ts:171–179）。CubeTextureManager 这一步（:281–286）记下 lost，退订所有 CubeTexture，清空缓存，通知 State。它不调用 deleteTexture：纹理已经随 context 一起失效了。退订的理由和第 15 课一样：CubeTexture 还活在 Scene 里，不退订的话，它的订阅会一直拽着这个旧 Manager。
  • 事件还在排队、context 已经丢了：先发现，不乱删。get 开头的 assertReady 问 isContextLost（:306–312）；上传到一半丢了，catch 先判断丢失、作废并抛 WebGLContextLostError，不去删已经失效的纹理（:180–183）；上传作用域的 finally 也不发还原命令。
  • 恢复以后：新 Manager，空缓存，重新上传。第 2 代的 CubeTextureManager 什么都没有。第一次画背景时 get 重新上传六面。像素从哪来？CubeTexture 一直借着那六张图，从来不关闭它们（CubeTexture.ts:335–344），所以不用重新下载 JPEG。CPU 对象就是重建的原料（第 4 课）。

5. 架构视角：对照 three.js r177

  • three.js 已经不支持 WebGL1。r163 起就去掉了（WebGLRenderer.js:61），r177 只建 webgl2 context。WebGL2 没有 NPOT 限制，sRGB 也是内置格式，所以这一课 validateStorage 里的 NPOT 和 EXT_sRGB 两条，在 three.js r177 里根本不存在。本项目要在 WebGL1 上跑，就得自己查。
  • 上传设置：每次都设，但不还。three.js 上传 cubemap 前，按纹理自己的字段设四个上传设置（flipY、premultiplyAlpha、unpackAlignment、颜色转换，WebGLTextures.js:1304–1307），之后不还原。它可以这样做，因为它独占这个 context，每次上传都自己重设一遍，从不假设旧值。本项目在迁移期间和旧引擎共用一个 context，所以多做一步「还回去」。
  • sRGB：同一个思路。three.js 对 sRGB 的 8 位纹理用 SRGB8_ALPHA8 内部格式（WebGLTextures.js:213），也是让 GPU 在采样时解码，和本项目用 EXT_sRGB 一样。
  • 更新：版本号 vs 不可变。three.js 的纹理可以改了再设 needsUpdate，靠 source.version 判断要不要重新上传（:1296）。本项目的 CubeTexture 上传后就是静态的，要换图就建一个新的 CubeTexture，Manager 只按对象身份缓存。

6. 审查视角
