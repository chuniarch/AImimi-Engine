滚轮缩放：为什么是「距离乘一个数」

滚一格滚轮，相机朝目标点靠近或远离。最直接的写法是「每格走 5 个单位」，可项目写的是 Math.exp(deltaY × 0.001)：每格把距离乘一个数。这一课从两个手感要求出发，推出只能这样写。

默认你已经会的：第 32 课的 ★ 和「同样长的东西，占的像素和深度成反比」（第 32 课第 8 节）。指数只用到「q 的 n 次方」这个意思。
这一课讲的：屏幕大小和距离的关系；要求一「每格放大同样的比例」推出乘法；要求二「分几次滚和一次滚完结果一样」推出指数；项目的 onWheel 逐行读（含 WheelEvent 的全部字段）；两种写法并排滚一滚。

1. 要回答的问题

相机离目标点的距离记作 r。HW2 一开始 r = 50.99。你向上滚一格，画面放大一点。问题是：这一格之后，r 应该变成多少？

滚轮缩放只改 r，不改相机看的方向，相机始终沿着「相机—目标」这条线前后移动。所以目标点一直在画面正中，它的深度就是 r。

2. 屏幕上的大小和距离成反比

在目标点那里竖一根长 L 的棒（垂直于视线）。由第 32 课的 ★，它在屏幕上占的像素是：

像素长度 = L × H / h(r) = L × H / (2 × r × tan(fovY/2))

L、H、fovY 都不变，变的只有 r。所以像素长度和 r 成反比：r 减半，棒在屏幕上的长度翻倍。HW2 里一根 2 个单位长的棒：

r = 50.99：2 × 600 ÷ (2 × 50.99 × 0.41421) = 28.41 px
r = 25.50：56.82 px（r 减半，长度翻倍）

（下面实验台的画布只有 240 px 高，读数会小得多；而且 HW2 的相机低着头，竖直的棒和视线不完全垂直，读数还会再小 2% 左右。这两件事都不影响比例：r 减半，长度照样翻倍。）

3. 要求一：每格放大的比例一样 → 乘法

第一个手感要求：不管现在离多远，滚一格，画面都放大同样的比例。比如每格都放大 10%。离得远时滚一格只动一点点，离得近时滚一格就猛冲过去，都是不好的手感。

写成式子。设滚一格前距离 r，滚一格后 r'，放大比例是 k（比如 1.1）。由第 2 节，大小和距离成反比：

新大小 ÷ 旧大小 = (1/r') ÷ (1/r) = r ÷ r' = k
⟹ r' = r ÷ k

不管 r 是多少，每格都是「除以同一个 k」，也就是乘同一个数 1/k。这就是乘法。

对照「每格走 5 个单位」（r' = r − 5），它放大的比例是 r ÷ (r − 5)，随 r 变：

r = 50.99 → 45.99：放大 50.99 ÷ 45.99 = 1.109 倍（约 11%）
r = 10    → 5    ：放大 10 ÷ 5        = 2 倍    （一格就翻倍）
r = 4     → −1   ：距离变成负数，相机穿过了目标点

乘法没有这个问题：一个正数乘一个正数，结果永远是正数，相机永远到不了目标点上，更不会穿过去。

4. 要求二：分几次滚和一次滚完一样 → 指数

浏览器交来的不是「格」，而是一个数 deltaY（第 38 课细讲）。鼠标滚一格常见的是 100 左右（不同系统、不同鼠标不一样，第 38 课的实验台会显示你的鼠标给多少）；触控板一滑，会发很多个 wheel 事件，每个只有几到十几。

第二个手感要求：同样的滚动量，分几次来和一次来，结果要一样。触控板滑 10 个 deltaY = 10，和鼠标滚一格 deltaY = 100，应该缩放得一样多。

设「收到 deltaY = Δ 以后，r 乘上 g(Δ)」。先收到 a、再收到 b，r 乘了 g(a) × g(b)；一次收到 a + b，r 乘了 g(a + b)。要求两者相等：

g(a + b) = g(a) × g(b)          对任意 a、b 都成立

只用这一条，就能一步步推出 g 长什么样：

  1. Δ = 0 时不缩放：取 a = b = 0，g(0) = g(0) × g(0)，所以 g(0) = 1。
  2. 整数：取 a = b = 1，g(2) = g(1)²；再加一个 1，g(3) = g(1)³……记 q = g(1)，就有 g(n) = qⁿ。
  3. 分数：把 1 拆成 m 份，1/m + 1/m + … + 1/m（m 个）= 1，所以 g(1/m)ᵐ = g(1) = q，g(1/m) = q^(1/m)。再用第 2 步，g(n/m) = q^(n/m)。
  4. 负数：g(Δ) × g(−Δ) = g(0) = 1，所以 g(−Δ) = 1 / g(Δ) = q^(−Δ)。向上滚一格和向下滚一格正好抵消。

所以 g(Δ) = q^Δ：滚动量出现在指数上（再加上「g 连续变化」这个自然的要求，无理数也一样）。数学里习惯把 q 写成 e 的某次方：q = e^c，于是

g(Δ) = e^(c × Δ)        c 是一个常数，决定滚一下缩放多快

e ≈ 2.71828。e^(c × Δ) 和 q^Δ 是同一个东西换了写法：选好 c，q 就定了。项目取 c = zoomSpeed = 0.001：

deltaY = +100（向下滚一格）：r × e^0.1  = r × 1.10517   相机后退约 10.5%
deltaY = −100（向上滚一格）：r × e^−0.1 = r × 0.90484   相机前进
                              画面放大 1 ÷ 0.90484 = 1.10517 倍
10 次 deltaY = 10：r × (e^0.01)^10 = r × e^0.1，和一次 100 完全一样

5. 两种写法并排滚一滚

左边是项目真实的 mountOrbitCameraInput（乘以 e^(0.001 × deltaY)），右边是课程写的「每格走 5 个单位」。在画布上滚轮，或者点按钮。读数显示上一格前后的距离 r，以及目标点处一根 2 个单位长的竖棒在屏幕上的长度。试试：

  • 速查：相机控制的数学（第 32–35 课的公式和数字都在这一页）。
  • 两边都连续向上滚：左边每格放大的比例一直是 1.105 倍；右边越滚越猛，最后穿过目标点，目标点从画面上消失。
  • 左边向上滚一格、再向下滚一格：r 回到原来的数。

6. 项目代码：onWheel 逐行读

    
滚轮事件交给这个函数（mountOrbitCameraInput.ts:296–306），注释是课程加的。函数前面那段注释列出 WheelEvent 的全部字段，依据是 MDN：WheelEvent 和 W3C Pointer Events 规范（WheelEvent 的定义已经从 UI Events 规范移到了这份规范）。函数里每一行的注释写着这一行用到哪个字段、哪条数学。

    
10 月 19 日补充：按你的建议，注释里加上了 WheelEvent 的字段和每一行用到的数学，applyOrbit 的节选也扩成了整段。项目代码本身没有变。


// ── WheelEvent 有哪些字段（MDN；W3C Pointer Events 规范）──
// 用到它的事件只有一种：wheel。滚轮、触控板滑动、触控板捏合都发它；
//   旧的 mousewheel、DOMMouseScroll 不是标准事件，已经废弃
// 自己的 4 个，都只读：
//   deltaX     横向滚动量，往右为正
//   deltaY     纵向滚动量，往下为正：deltaY > 0，页面会往下滚
//   deltaZ     z 方向的滚动量，远离用户为正
//   deltaMode  上面三个数的单位：0 像素、1 行、2 页
// 从 MouseEvent 继承：clientX、clientY（指针在哪里）、
//   ctrlKey、shiftKey、altKey、metaKey（按着哪个修饰键）、
//   buttons（按着哪些鼠标键）等
// 从 Event 继承：cancelable（能不能取消）、preventDefault()
// 已经废弃，不要用：wheelDelta、wheelDeltaX、wheelDeltaY
//
// 这个函数只读 deltaY、deltaMode，只调用 preventDefault()。
// 不读的几个，为什么不读：
//   deltaX     横着滑不缩放。只横着滑的事件 deltaY = 0，第一行就返回
//   clientX/Y  总是朝目标点缩放，不朝指针所在的点
//              （three.js OrbitControls 的 zoomToCursor 选项做后者）
//   ctrlKey    按着 Ctrl 滚、触控板捏合缩放时为 true（第 38 课）。
//              这里不区分：捏合也走同一个公式
function onWheel(event: WheelEvent): void {
  // 已经卸载、deltaY 不是有限数、或者是 0：什么都不做。
  // 这里检查 deltaY 是有限数，之后放心：指数和 zoom 都是有限数。
  //   不检查的话 NaN 会一路传下去：e^NaN = NaN，r × NaN = NaN
  // deltaY = 0 时 e^0 = 1，r 不变，所以直接返回。返回得早，
  //   也就不调用 preventDefault：浏览器照常做自己的事（比如横向滚动）
  if (closed || !Number.isFinite(event.deltaY) || event.deltaY === 0) return
  const camera = getCamera()
  // 没有相机：不缩放，也不拦，页面照常滚
  if (camera === null) return
  // 拖动途中换了相机：先结束那次拖动（第 37 课）
  if (drag !== null && camera !== drag.camera) endDrag()
  // 把 deltaY 换成 CSS 像素：Δ = deltaY × unit
  //   deltaMode 0 像素：unit = 1
  //   deltaMode 1 行：  unit = 16（项目定的：1 行按 16 像素）
  //   deltaMode 2 页：  unit = 画布高度；画布看不见时高度是 0，至少取 1
  //   例：deltaY = 3（行）→ Δ = 48 像素 → zoom = e^0.048 = 1.0492
  // MDN：不要假设是像素；有的浏览器还会看你有没有读过 deltaMode，
  //   再决定给哪种单位。所以两个字段要从同一个事件里一起读
  // 乘一个正数只是换单位，第 4 节的 g(a + b) = g(a) × g(b) 照样成立
  const unit =
    event.deltaMode === 1
      ? 16
      : event.deltaMode === 2
        ? Math.max(1, canvas.clientHeight)
        : 1
  // 第 4 节的 g(Δ) = e^(c × Δ)，c = zoomSpeed = 0.001（每像素）：
  //   deltaY = +100 → e^0.1  = 1.10517：r 变大，相机后退
  //   deltaY = −100 → e^−0.1 = 0.90484：r 变小，相机前进
  //   触控板 10 个 +10：e^0.01 连乘 10 次 = e^0.1，和一次 +100 一样
  //   （指数相加：e^a × e^b = e^(a + b)）
  // clamp(v, 下限, 上限)：比下限小取下限，比上限大取上限（:40）。
  // 这里把指数限制在 ±50，之后放心：zoom 是有限的正数。
  //   Math.exp(x)：x > 709.78 得 Infinity，x < −745 左右得 0
  //   e^50 ≈ 5.18 × 10²¹，e^−50 ≈ 1.93 × 10⁻²²
  // ±50 不会让缩放变少：HW2 的 r 在 [1, 300] 里，两端只差
  //   300 = e^5.70 倍，一个事件的指数超过 ±5.70 就已经撞到边界
  const zoom = Math.exp(clamp(event.deltaY * unit * zoomSpeed, -50, 50))
  // 只缩放、不旋转：方位角、仰角的变化都是 0
  applyOrbit(camera, 0, 0, zoom)
  // 取消默认动作：页面不跟着滚；捏合时浏览器也不缩放整页（MDN）。
  //   要配合 passive: false 登记（:314，第 38 课），而且只对
  //   cancelable 为 true 的事件有效
  // 放在最后：上面提前返回的那几种情况，页面照常滚
  event.preventDefault()
}

    
applyOrbit 接着把 zoom 用到相机上（:138–163）。数字用 HW2 一开始的相机：位置 (0, 20, 50)，目标点 (0, 10, 0)。


// applyOrbit 节选；滚轮调用它时 azimuthDelta = elevationDelta = 0
const target = targets.get(camera) ?? initialTarget
const position = camera.transform.position
// 从目标点指向相机的向量 (x, y, z)：
//   (0, 20, 50) − (0, 10, 0) = (0, 10, 50)
const x = position[0] - target[0]
const y = position[1] - target[1]
const z = position[2] - target[2]
// 勾股定理：水平面上的长度 √(x² + z²) = 50
const horizontal = Math.hypot(x, z)
// 再用一次：r = √(horizontal² + y²) = √(x² + y² + z²) = 50.99
const distance = Math.hypot(horizontal, y)
// 这里检查 r 是有限数，之后放心：下面的乘法、三角函数都得有限数
if (!Number.isFinite(distance)) return

// r' = r × zoom，再限制在 [minDistance, maxDistance]（HW2 是 1 到 300）。
// distance || minDistance：r = 0（相机正好在目标点上）时改用
//   minDistance。0 乘任何数都是 0，不换的话怎么滚都离不开目标点
// 限制会让「上下各一格正好抵消」在边界附近不成立：
//   r = 290，往下一格：290 × 1.10517 = 320.50 → 限制成 300
//   再往上一格：300 × 0.90484 = 271.45，回不到 290
const radius = clamp((distance || minDistance) * zoom, minDistance, maxDistance)
// 从 (x, y, z) 反算两个角（第 35 课细讲），再加上变化量 0：
//   方位角 = atan2(x, z)：水平面上偏离 +z 轴多少，HW2 是 0°
//   仰角   = atan2(y, horizontal)：相机在目标点上方多少度，HW2 是 11.31°
const azimuth = (Math.atan2(x, z) + azimuthDelta) % TWO_PI
const elevation = clamp(
  Math.atan2(y, horizontal) + elevationDelta,
  // 仰角限制在 ±(90° − 0.057°)：正上方时方位角没有定义
  -MAX_ELEVATION,
  MAX_ELEVATION
)
// 球坐标 → 直角坐标：相机 = 目标 + radius × 单位方向，
//   单位方向 = (cos 仰角 × sin 方位角, sin 仰角, cos 仰角 × cos 方位角)
// 两个角没变，单位方向就是原来的 (x, y, z) ÷ r，所以
//   相机 = 目标 + (radius ÷ r) × (x, y, z)：只把那个向量拉长或缩短
//   HW2 往上滚一格：(0, 10, 0) + 0.90484 × (0, 10, 50)
//                 = (0, 19.05, 45.24)
const ringRadius = radius * Math.cos(elevation) // 水平面上的那一段
const next: Vec3Tuple = [
  target[0] + ringRadius * Math.sin(azimuth),
  target[1] + radius * Math.sin(elevation),
  target[2] + ringRadius * Math.cos(azimuth)
]
// Transform 保存 Float32，不能把溢出的输入写成 Infinity 而破坏下一帧矩阵。
//   ↑ 这一行是项目原有的注释。Float32 最大约 3.4 × 10³⁸，比 double 小
//   得多：这里检查转成 Float32 后仍是有限数，之后放心：矩阵里没有 Infinity
if (!next.every((value) => Number.isFinite(Math.fround(value)))) return
camera.transform.setPosition(next)
// 朝向也按这两个角设，相机继续看着目标点（第 35 课）
camera.transform.setRotation([-elevation, azimuth, 0])

    
合起来：滚轮缩放只把「目标点 → 相机」这个向量乘上 zoom（碰到距离限制时乘得少一些），相机沿着这条线前后移动，目标点一直在画面正中。
